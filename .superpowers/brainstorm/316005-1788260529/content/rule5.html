Rule 5 — animation never gates interaction

Your constraint, written to be falsifiable, then run against everything already decided.

Rule 5. Where no real work is happening, the user can act at any point during the motion. Motion may describe a state change; it may never delay one.

Where there genuinely is a wait — an RSC fetch, a mutation in flight — the animation may cover that wait, but it may not add latency of its own.

The test: at every frame of the animation, is the control the user is reaching for hit-testable? Not visible — hit-testable. That is a measurement, not a judgement.

Where it bites: my own sidebar design

I delayed the expand pill until the panel had fully gone, so two things never moved at once. That was a rule-1 instinct applied where rule 5 governs. For 220ms after you collapse the sidebar there is no way to re-expand it with the mouse. Try clicking the bottom-left corner immediately after collapsing.

The one real conflict: the card → modal morph

The spec records this as decided — a 320ms same-document startViewTransition(). Measured in the running app just now:

during document.startViewTransition() (320ms animation) elementFromPoint at a fixed z-index:99999 button returns HTML on 12 of 12 sampled frames — the live DOM is not hit-testable for the whole transition. Pointer input is dead. keydown listeners 12 of 12 delivered, first at 2ms — keyboard is NOT hit-tested, so Escape, Tab and typing all keep working throughout. → the block is pointer-only, and it is inherent to the API, not to our timing. Shortening the duration shortens the block; it does not remove it.

Keep the morph as specified

Argue that opening a task is committing to the modal, so 320ms of dead pointer is acceptable for that one gesture. Keyboard still works. Rule 5 gets a written, dated carve-out naming the API as the cause.

Keep it, shortened to ~180ms (recommended)

Same effect, roughly half the dead window, still clearly a morph. The carve-out is still needed but is much cheaper. 320ms was chosen before this constraint existed.

Drop the morph

Open the modal with a front-loaded fade like the menu — nothing blocks, no carve-out, rule 5 holds everywhere with no exceptions. Cost: loses the single most distinctive transition in the phase.
