1 · The one state change here that genuinely snaps

+ Add New Task is disabled until the open board has a column. Create that first column and the button becomes usable — a state change the user caused. Disabled stops being “the brand colour, faded” and becomes its own token trio — surface --bg-app, text --text-muted, border --border. That is a colour change, so it rides transition-colors at 130ms with no new property, no opacity, and no geometry — rule 1 and rule 3 both hold. It also reads better: a translucent fill washes the label out along with the button, which is why the current disabled state is hard to read at all. Sign Out picks up the same idle → loading contract the spec already fixed for the auth form. Both buttons also show the app-wide 4px radius replacing rounded-full.

2 · The board title

Rename → one-frame swap (recommended)

A rename has no direction. Sliding it implies the title travelled from somewhere, which is rule 2's complaint. Rule 4 explicitly allows the one-frame swap; the board switch keeps its directional slide because navigation does have a direction.

Rename → slide too

One mechanism for every title change, so there is only one thing to build and test. Cost: the direction is invented, and the sidebar row renaming underneath it does not slide, so the two disagree about what just happened.

3 · What I am deliberately not adding

No scroll-elevation on the header. The obvious restrained-precision move is a border or surface that reacts as content scrolls under the header. Measured: nothing ever scrolls under it. The board scrolls horizontally in its own container and each column scrolls vertically in its own — main.scrollHeight === main.clientHeight (647 = 647). There is no trigger, so the state would never fire. Recording it here so a later reader does not "fix the oversight".
