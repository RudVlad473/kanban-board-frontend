The rule, generalised: text never crossfades. A card can crossfade because it is a rectangle at every intermediate frame. Two strings cannot — different widths and different glyphs mean every intermediate frame is noise. So any changing text in this app either swaps in one frame or moves behind a mask. That covers the board name, column names after a rename, the task count pills, and the subtask 2/3 caption.
Between 2 and 3. Option 2 is the more honest one: the board name is already in the client from the sidebar, so there is no latency to represent and a slide invents motion where nothing was waiting. Option 3 buys spatial continuity with the columns, at the cost of ~180ms of movement on a value that was never pending. I lean 2, but 3 is defensible if you want the header to feel part of the same gesture as the columns rather than a separate instant thing.
