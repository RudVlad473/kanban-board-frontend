What actually changed, in rough order of how much it contributes:
• A real focus state. Border goes purple and a 2px outline sits 1px off the edge. Tab through both panes — today's border-colour-only focus is nearly invisible.
• The message line is always in the layout (min-height:16px, opacity-toggled), so an error never pushes the field below it down. Today's error shifts the password field on blur.
• Leading icons and placeholders give each field interior structure, so a field reads as a field rather than an empty rectangle.
• Radius agrees with the card — 6px inputs inside a 12px card, rather than today's 4px inside 8px, which reads as two unrelated systems.
• Server errors get a bordered block at the top of the form rather than a bare red sentence floating between the field and the button.
• The button has states — idle, loading with a spinner and changed label, then a brief confirmed state before navigation.
• Caps-lock hint and a password strength meter (sign-up only), plus real autocomplete values so password managers behave.
A conflict with our own rule, resolved explicitly. Rule 1 says hover and focus change colour only — "never shadow." A focus halo drawn as box-shadow would break that. So focus rings use outline with outline-offset, which paints outside the border box and cannot shift layout, matching what the primitives already do (focus-visible:ring-2 ring-ring-focus ring-offset-2). Rule 1 gets an explicit carve-out in the spec: focus rings are an accessibility affordance, not elevation, and are exempt. Better to write the exception down than to leave a rule that the codebase visibly violates.
