Pending as opacity — how much is the whole question

Option 2's geometry stays: pending sits 2px down with the bottom edge gone, so it is visibly already pressed. The only variable below is how far the fill fades.

The contrast objection I raised does not actually apply here. WCAG 1.4.3 and 1.4.11 both exempt inactive user interface components from every contrast requirement, and a button you cannot click is inactive. So today's opacity-50 was never a violation, and none of the values below are either — this is a legibility judgement, not a compliance one. Numbers are printed anyway, because "allowed" and "readable" are different questions.

Where the fade is applied

Both are 75% — the decided value. The difference is whether the progress signal fades along with the button.

Fade everything. opacity: .5 on the button. One line, and the spinner and rail recede with it — the busier the button looks, the less you can see it is busy.

Fade the fill and label only. The spinner and rail stay at full strength. Costs one wrapper element around the label; the progress signal survives at any opacity you pick.
