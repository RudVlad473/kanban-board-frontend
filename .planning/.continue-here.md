## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Blindly retrying a failed `git push` without reading why | Twice this session an executor/orchestrator re-ran `git push` immediately after a pre-push failure instead of reading the actual output | advisory | Always inspect the failed run's real output (not a piped/truncated tail) before retrying; the failures both turned out to be real but unrelated CI-runner contention flakes, confirmed by isolated re-runs |
| Piping `git push` through `\| tail -N` when the exit code will be trusted | `git push 2>&1 \| tail -20` reported exit 0 even though the underlying push failed — the reported code was `tail`'s, not `git push`'s | advisory | Never pipe a command whose exit code matters; if you need to see only the tail, redirect to a file and separately check `$PIPESTATUS[0]` or the command's own exit code |
