# Quick Task 260905-r15: Reset the column-row scroll offset on a board switch

**`BoardScreen` now keys `BoardView` on `board.id`, so a switch mounts a fresh element tree instead of carrying the previous board's `scrollLeft` into the new board's column row — pinned by an e2e case falsified against the unfixed code first.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 2 of 3 completed in full; Task 3's gate work done, push/CI deferred to the orchestrator (see below)
- **Files modified:** 4 (3 code, 1 docs)

## Root cause and fix

`BoardScreen` is mounted by the dashboard layout, which Next does not re-render on a `[boardId]`-only navigation, so `BoardView` — and the one DOM element for its horizontal, `overflow-x-auto scroll-smooth` column row — survived a board switch unchanged. Scrolling board A's row and then switching to board B left B rendered inside that same scrolled element, so B's row opened at board A's `scrollLeft` whenever B also overflowed.

Fix: `BoardScreen` renders `<BoardView key={board.id} board={board} />`. A new key makes React unmount the old tree and mount a fresh one — the column row is a new DOM element that starts at `scrollLeft = 0` with nothing to animate — instead of hand-rolling scroll-restoration bookkeeping (an effect or ref writing `scrollLeft = 0`) that CLAUDE.md's "reach for the platform's own primitive" rule explicitly rejects. Nothing about the query, `initialData` seed, the invalidate-on-switch effect, or `docs/adr/tech/0030`'s cache shape changed.
