<technique_contract>
The technique is fixed and must not be substituted without saying so explicitly in the SUMMARY.

Next.js 16 App Router officially supports `window.history.pushState` / `replaceState` for URL
changes — documented under "Linking and Navigating -> Native History API" and "Single-Page
Applications -> Shallow routing on the client". These calls integrate with the Next router and
**synchronously update `usePathname()` / `useSearchParams()` without issuing an RSC request for the
new segment.** That is the platform primitive this task reaches for; do not hand-roll a routing shim
around it, and do not reach for `router.push`, a transition, or a custom pathname store.

Two independently verified reasons this property is exactly what is needed here — both grounded in
files read at planning time:

1. `src/components/layout/board-view/board-screen.tsx` resolves its board id from
   `toBoardIdFromPath(usePathname())` — inlined there by 260908-g61, which deleted the hook that
   used to wrap it — and paints from the `buildBoardQueryKey(id)` cache entry. A `pushState`
   therefore repaints the new board in the same frame, with no network in the way. Post-g61 there
   is no delete-aware override between the pathname and the id, which makes this path shorter than
   the one the pre-g61 plan described, not longer: nothing else can win over the pushed URL.
2. `app/(dashboard)/boards/[boardId]/page.tsx`'s T-02-54 membership redirect runs only on a real RSC
   navigation. A `pushState` does not trigger one, so that deliberate guard is neither weakened nor
   bypassed — it simply is not consulted for a board the client already knows about. **Do not plan
   or make any change to that guard.** Authorization is unaffected either way: the dashboard
   layout's own `verifySession()` and the backend's per-user reads are what protect the data; the
   guard is a UX redirect.

    THE URL ROLLBACK MECHANISM — decided, with the justification recorded in the file's own comment.

    Use `window.history.replaceState(null, "", previousPath)`, not `window.history.back()`.
    `replaceState` is deterministic: it does not depend on where the history cursor currently sits,
    cannot overshoot when the user moved twice, and is synchronous, so the URL rollback lands in the

    board) the two agree, so `back()`'s only distinguishing behaviour is its failure mode. Its cost is
