<objective>
Find and fix the board-delete stranding bug: after confirming a board delete, roughly 520ms of the
just-deleted board's content and a blank header title are shown before the destination lands.

Purpose: the last queued item from Phase 04's 04-25 checkpoint. It is the same bug class this
repo has now fixed four times over (`260905-r15` board-switch scroll carry, `260906-hze` loading.tsx
fallback scope, `260905-s0l` reorder flicker, `260907-exb` fan-out non-optimism): a write is applied
optimistically in one place while the thing that MOVES the user is not, leaving a window where the
screen tells the user something untrue.

Output: a measured mechanism, an e2e case falsified in both directions, the production fix, and a
recorded quality baseline for the new case.
</objective>
