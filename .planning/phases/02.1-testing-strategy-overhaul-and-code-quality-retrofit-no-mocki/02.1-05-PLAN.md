Create three ADRs, each mirroring the existing files' structure.

`docs/adr/tech/0020-no-mocking-policy.md`:
- Status: Accepted. Extends 0018 from the HTTP layer to test doubles generally.
- Decision: no `vi.mock`, `vi.spyOn` or equivalent anywhere outside `*.stories.tsx`. A test isolates
  itself by creating throwaway data against the real deployed backend, never by faking a module.
  Storybook stories remain the one sanctioned place to stage fixture data.
- Carve-out (D-19), written in 0017's carve-out style: a narrow framework/environment shim is
  permitted where a named platform limitation makes the real module unusable in the test
  environment — the two standing examples are `next/headers`'s `cookies()` (no Next.js request scope
  exists in a Vitest run) and `next/link` under Vitest Browser Mode (its real implementation reads
  `process.env` at module evaluation and throws `ReferenceError: process is not defined`). Every such
  shim MUST carry an inline comment naming the specific limitation AND an
  `eslint-disable-next-line no-restricted-syntax` directive whose trailing reason states it. A mock
  of this project's own modules, of an API call, or of a hook is never permitted under this carve-out.
- Fixture construction (D-11): entity fixtures are built by factory functions taking
  `Partial<T>` overrides (`src/test-utils/factories/`), not by ad hoc per-test object literals and
  not by a class requiring `new`.
- Enforcement: the `no-restricted-syntax` selectors in `eslint.config.mjs`.
- Consequences: name the cost honestly — real-backend tests are slower and need the nonprod backend
  reachable, and a suite failure can now mean a backend problem rather than a code problem.

`docs/adr/tech/0021-storybook-driven-component-tests.md`:
- Decision (D-08): every component carries a co-located `*.stories.tsx` and a co-located
  `*.test.tsx` that imports those stories through `composeStories` and drives them with `.run()`.
  Shallow concerns — copy text, prop-driven variants, validation and error-state rendering — are
  asserted through composed stories, not through a hand-built render, so the stories and the tests
  can never describe different components.
- Mechanism: import `composeStories` from `@storybook/react`, never from `@storybook/nextjs-vite`,
  and record the reason in one sentence pointing at `vitest.setup.ts`'s own comment for the full
  explanation. Note that `setProjectAnnotations` is already wired in `vitest.setup.ts` and must not
  be re-wired.
- Scope carve-out: `app/**/error.tsx` and `app/**/layout.tsx`-style route files are exempt from the
  stories requirement — they are thin route wrappers composing components that carry their own
  stories (`ErrorFallback` is the worked example); their existing co-located tests stay.
- Hook carve-out (D-09): non-visual hooks are tested with React Testing Library's `renderHook` in
  the jsdom `unit` project, never in Vitest Browser Mode. A hook whose behaviour depends on real
  layout measurement (`scrollWidth`/`clientWidth`, `ResizeObserver`) is the stated exception and
  stays in the `browser` project — `useOverflowIndicator` is the worked example and the reason.
- Enforcement: `pnpm test:browser`; a component without a stories/test pair is a review-blocking gap.

`docs/adr/tech/0022-e2e-scope-and-seeding.md`:
- Decision (D-05): Playwright e2e specs cover only real business-logic happy paths — create, view,
  switch, edit, drag/move, delete including cascade, sign-in/out, theme switching. They must NOT
  assert on validation error copy, microcopy text or edge-case error-state rendering; that coverage
  lives in component-level composed-story tests per 0021.
- Decision (D-06): every e2e test body (or each logical block within a longer flow) carries explicit
  `// Arrange` / `// Act` / `// Assert` comments.
- Decision (D-07): e2e data seeding is a curl-based CLI, not TypeScript fixture helpers. Record the
  constraint it must preserve: the backend caps one account at two concurrent sessions, so seeding
  reuses the sign-up response's own session credential via a cookie jar rather than signing in a
  second time.
- Enforcement: code review plus `pnpm exec playwright test --project e2e` against the real deployed
  nonprod backend.
