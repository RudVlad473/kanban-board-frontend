# Phase 02.1: Testing Strategy Overhaul & Code-Quality Retrofit - Context

**Gathered:** 2026-08-21
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase adds no new user-facing capability. It is a foundational retrofit, applied
retroactively across everything Phase 1 (Foundation/Auth/Preferences, 38 plans) and Phase 2
(Board Management, 8 completed plans) have built so far, covering two intertwined concerns:

1. **Data-fetching architecture** — Route Handlers are banned; every server entry point becomes
   either a React Server Component (reads) or a Server Action (writes, and reads consumed
   client-side). This revises ADR tech/0002.
2. **Testing strategy** — no mocking anywhere outside Storybook; E2E covers only real
   business-logic happy paths against the real backend, seeded via a curl-based CLI instead of
   TypeScript fixture helpers; every component gets a co-located Storybook stories file AND test
   file, with the test file importing the stories to cover shallow concerns (copy, validation,
   error states) that E2E no longer touches; hooks are tested with React Testing Library instead
   of Vitest Browser Mode.

A durable documentation step (CONVENTIONS.md + new/revised ADRs) is an explicit deliverable of
this phase, not incidental — future sessions must inherit this context without re-litigating it.

Phase 2's remaining plans (02-09 through 02-13) are intentionally paused until this phase closes,
so they get built on the corrected patterns from the start rather than needing their own retrofit
later.

</domain>

<decisions>
## Implementation Decisions

### Data-fetching architecture (revises ADR tech/0002)
- **D-01:** Route Handlers (`app/api/**/route.ts`) are banned project-wide as a data-access
  mechanism. — **Reversibility:** costly — no published external contract depends on them, but
  reverting means reintroducing the Route Handler layer across every feature that adopts this
  decision.
- **D-02:** Every server entry point is either a React Server Component (server-side reads, no
  client-side query for list/detail data) or a Server Action (writes — create/rename/delete/
  move/reorder — invoked directly by an RSC/form, or wrapped as a TanStack Query
  `mutationFn` when client-side optimistic `onMutate`/`onError` rollback is needed). This is a
  blanket rule every future plan applies without re-deciding, not a per-feature judgment call. —
  **Reversibility:** costly — touches every board/column/task data-fetching call site already
  built, and every later phase's plans copy this pattern forward.
- **D-03:** 02-08's `app/api/boards/route.ts` + `useBoards()` (TanStack Query for reads via a
  Route Handler) is retroactively non-compliant and must be rebuilt on RSC as part of this
  phase's own retrofit work — it is in scope, not exempted because it just merged.

### Testing policy
- **D-04:** No mocking (`vi.mock`, `vi.spyOn`, or equivalent) anywhere outside Storybook story
  files. Currently 14 of 46 test files use `vi.mock`/`vi.spyOn` and must be rewritten to not.
  Storybook stories remain the sanctioned place to stage fixture data.
- **D-05:** E2E tests (Playwright, real deployed backend) cover only real business-logic happy
  paths — create, view, switch, edit, drag/move, delete (including cascade deletes), sign-in/out,
  theme switching, etc. They must NOT assert on validation error copy, microcopy text, or
  edge-case error-state rendering — that moves to component-level shallow tests (D-08).
- **D-06:** E2E test bodies follow an explicit Arrange-Act-Assert commenting convention — each
  test (or logical block within a longer flow) is marked with `// Arrange`, `// Act`,
  `// Assert`-style comments.
- **D-07:** E2E data seeding migrates from the TypeScript fixture helpers in `e2e/fixtures.ts`
  (`createFixtureAccount`/`createFixtureBoard`) to a curl-based CLI mechanism. Exact shape
  (standalone script vs. Playwright global-setup step, where it lives) is Claude's discretion —
  see below.
- **D-08:** Every component gets a co-located Storybook stories file (if missing) and a
  co-located test file that imports those stories (via Storybook's portable-stories /
  `composeStories`) to cover shallow concerns — copy text, prop-driven variants, validation and
  error-state rendering. This is what absorbs the coverage E2E gives up per D-05.
- **D-09:** Hooks (non-visual — `useBoards` today, any future non-rendering hook) are tested with
  React Testing Library's `renderHook`, not Vitest Browser Mode. Browser Mode stays reserved for
  actually-rendered UI components.
- **D-16:** Retrofit breadth is a **full retroactive rewrite** — every test file across Phase 1
  and Phase 2 that violates any policy above is brought into compliance, not just the 14
  mock-using files (explicitly chosen over a narrower targeted-fix option). —
  **Reversibility:** costly — large surface area; the user chose this explicitly over the
  smaller alternative Claude proposed.
- **D-17:** Two loosely-matched pending todos (theme cookie not cleared on sign-out; path
  traversal in `scripts/serve-static.mjs`) stay OUT of this phase's scope — kept separate, not
  folded in.

### Code quality (from 02-08's deferred code review)
- **D-10:** A typed, reusable cookie client replaces the ad hoc `themeCookie`/`upstreamCookie`
  modules — a single generic, typed abstraction for reading/writing/clearing named cookies.
  `session.ts`'s own bespoke cookie handling is refactored to consume this same client rather
  than shipping its own implementation.
- **D-11:** An abstract class (or whatever TS pattern research determines is idiomatic — factory
  function, base class, etc.) standardizes test/fixture entity creation, replacing ad hoc
  per-test object literals. Exact shape is Claude's discretion.
- **D-12:** `isBoard`/`isBoardArray` hand-written runtime guards are replaced with **zod** schema
  validation at the API boundary (zod is already a project dependency, unused so far — no new
  library needed). The same pattern extends to other DTOs with the same "no `required` array"
  problem as Column/Task/Subtask are built.
- **D-13:** Scattered top-level exported test-config constants (`E2E_SESSION_SECRET`,
  `E2E_EXTERNAL_API_BASE_URL`, `E2E_PORT`, `E2E_BASE_URL`, etc.) are grouped using the
  **already-locked ADR tech/0012 pattern** — a `const` object literal with `as const` — NOT
  TypeScript's `enum` keyword, which tech/0012 explicitly forbids. This is an existing project
  convention being applied, not a new decision.
- **D-14:** API route path literals are replaced with OpenAPI-generated/declared route constants
  — extending the `EXTERNAL_PATH` pattern 02-08 already established in
  `src/lib/core/api-contract/external-paths.ts` — instead of hand-written string literals
  scattered through Route Handlers/Server Actions/components.
- **D-15:** `boardDetail` (a function that builds a route path, not a constant) is renamed to a
  verb-form name. Exact name is Claude's discretion.

### Documentation (must land before/alongside the retrofit)
- **D-18:** All decisions above are written down as durable, discoverable project conventions —
  CONVENTIONS.md updates plus new/revised ADRs, following the existing `docs/adr/tech/NNNN`
  numbering and the tech/0017-carve-out / tech/0018-supersession precedents — so future sessions
  inherit this context without re-litigating it. This is an explicit phase deliverable, not
  incidental cleanup.

### Claude's Discretion
- Exact shape of the curl-based E2E seeding mechanism (D-07): standalone shell script vs.
  Playwright global-setup step, and where it lives in the repo.
- Exact TS pattern for the mock/fixture-entity abstract class (D-11).
- Exact naming for the renamed `boardDetail` function (D-15) and the file/module the
  zod-replaced type guards move to (D-12).
- Whether zod validators live inline per-feature or as a shared module under
  `src/lib/core/api-contract/`.
- New ADR count/numbering (D-18) — likely several new/revised ADRs mirroring the existing
  one-concern-per-ADR granularity (0001-0018), not one giant consolidated document.

  (`.planning/todos/pending/2026-08-20-clear-theme-cookie-on-sign-out.md`) — loosely matched
