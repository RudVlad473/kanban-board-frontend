## Decisions Made

- **`sign-out-action-storybook-stub.ts` created during Task 1, not Task 3.** Vite's browser-
  project dependency scan eagerly resolves every file the project's `include` glob matches
  (every `*.test.tsx` under `src/`/`app/`), not just the file Vitest was asked to run — so
  `sign-out-button.test.tsx`'s still-unmocked import of `@/features/auth/actions/sign-out`
  failed to resolve against Task 1's own new alias entry before a real target file existed.
  Created a minimal, comment-length-compliant version in Task 1 (Rule 3 blocking-issue fix);
  Task 3 added the invocation-recording accessors on top.
- **No separate `BadCredentials`/`DuplicateAccount` composed stories.** Both `sign-in.ts` and
  `sign-up.ts` collapse every failure cause to one fixed message each (confirmed by reading both
  action files directly) — a second story staging the same fixed string via a different prop
  value would assert byte-identical output. One `WithServerError` composed-story test per form
  proves the form renders `state.message`; the real per-cause-collapses-to-one-code guarantee is
  what `sign-in.integration.test.ts`/`sign-up.integration.test.ts` (02.1-06) already prove
  against the real backend.
- **FormData-submission-content coverage preserved via a real `submit` DOM event listener**, not
  dropped. `rendered.container.querySelector("form")?.addEventListener("submit", (event) => {
  submitted.formData = new FormData(event.target as HTMLFormElement); })` reads the browser's own
  assembled FormData after a real click — no mock, no test double, and still proves the fields'
  `name` attributes wire correctly.
- **Dropped Deep tests that depended on gating/rejecting a mocked action's return value**
  (optimistic-ordering timing, loading-state-via-gated-promise, post-rejection password-clearing/
  field-recovery) since the aliased stub always resolves success synchronously and cannot be
  configured per-test. The rendering these protected now lives in Shallow composed-story tests
  (`Submitting`/`WithFieldErrors`/`WithServerError`) driven by each component's own `forceX`
  staging props — this mirrors Task 1's own theme-toggle `SaveFailed` treatment exactly, which
  the plan's Task 1 action text explicitly directs.
- **`SignOutButton` gets no `Pending` story.** Unlike the other three components, it has no
  `forceX` prop to stage a pending render, and `sign-out-button.tsx` is 02.1-12's sweep scope,
  not this plan's — documented rather than silently dropped.
