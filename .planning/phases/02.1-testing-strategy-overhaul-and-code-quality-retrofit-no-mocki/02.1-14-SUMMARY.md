## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `.storybook/vitest.setup.ts`'s compressed comment accidentally re-triggered `@storybook/addon-vitest`'s auto-provisioning-disable detector**
- **Found during:** Task 1, verifying `pnpm exec vitest run --project storybook` after the first round of edits
- **Issue:** `@storybook/addon-vitest`'s `requiresProjectAnnotations()` (in its vitest plugin) does `readFileSync(setupFile, "utf-8").includes("setProjectAnnotations")` on any setup file whose `dirname` equals the Storybook `configDir` (`.storybook/`) — a naive substring match, not an AST check. My first compressed comment in `.storybook/vitest.setup.ts` described the absence of a manual `setProjectAnnotations()` call using that exact word, which the detector read as presence of the call and disabled its own automatic per-story annotation provisioning — breaking all 94 tests in the "storybook" Vitest project with `SB_PREVIEW_API_0014 NoRenderFunctionError`. Confirmed the root cause by reading the addon's compiled source directly (`node_modules/.../addon-vitest/dist/vitest-plugin/index.js:2380`) and by bisecting against pristine files (which passed reliably) versus the edited file (which failed deterministically once transient environment resource contention — separately observed and resolved by killing lingering `chrome-headless-shell.exe` processes — was ruled out).
- **Fix:** Reworded `.storybook/vitest.setup.ts`'s comment to describe the constraint without writing the literal identifier as contiguous text, and documented the gotcha explicitly in `docs/adr/tech/0021`'s Mechanism section as a hard rule for future editors of that specific file.
- **Files modified:** `.storybook/vitest.setup.ts`, `docs/adr/tech/0021-storybook-driven-component-tests.md`
- **Verification:** `pnpm exec vitest run --project storybook` — 94/94 pass, re-confirmed on a second clean run.
- **Committed in:** `10fa1da` (Task 1 commit)

**2. [Rule 3 - Blocking] `pnpm build` fails without `SESSION_SECRET`/`EXTERNAL_API_BASE_URL` — no `.env.local` exists in this worktree**
- **Found during:** Task 2's verification (`pnpm lint && pnpm test && pnpm build`)
- **Issue:** This worktree has no `.env.local`; `next build` throws `SESSION_SECRET is not set` while collecting page data for `/boards/[boardId]` (ADR tech/0001's fail-fast guard). Pre-existing environment gap, unrelated to this plan's comment-only diff — every other verification command (tests, lint) already supplies its own test-only fallback via `vitest.config.ts`/`e2e/test-env.ts`, but `next build` does not.
- **Fix:** Set `SESSION_SECRET` (a freshly generated value) and `EXTERNAL_API_BASE_URL` (the nonprod backend URL already used by the passing integration tests) as shell-scoped environment variables for the `pnpm build` invocation only — no files written, nothing committed.
- **Files modified:** None (shell environment only).
- **Verification:** `pnpm build` completes successfully with all 6 routes compiled.
- **Committed in:** N/A (no file change)
