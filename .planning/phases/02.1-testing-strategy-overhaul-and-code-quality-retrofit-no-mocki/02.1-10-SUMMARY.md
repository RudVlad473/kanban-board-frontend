# Phase 02.1 Plan 10: Curl-Based E2E Seeding & Scope Narrowing Summary

**Replaced `e2e/fixtures.ts`'s TypeScript/Playwright seeding helpers with a curl-based CLI
(`e2e/seed.sh` + `e2e/seed.ts`), rescoped all four e2e specs to real business-logic happy paths,
and gave every test body explicit Arrange/Act/Assert structure.**

## Accomplishments

- `e2e/seed.sh` — a bash CLI with `account`/`board` subcommands, using a curl cookie jar
  (`-c`/`-b` against a `mktemp` file) to carry the sign-up session's own credential into board
  creation, so seeding spends none of the backend's two-concurrent-session-per-account budget.
  Verified directly against the real deployed nonprod backend: account creation, board creation
  reusing the same `JSESSIONID`, and the non-2xx error path (a bad session returns `401`, exits
  1, prints status + body to stderr).
- `e2e/seed.ts` — a thin typed wrapper (`seedAccount()`, `seedBoard()`) invoking `seed.sh` via
  `spawnSync("bash", ...)`, throwing on nonzero exit with the script's own stderr. Verified
  directly (a throwaway vitest integration test, deleted after use) against the real backend.
- `e2e/fixtures.ts` deleted — `createFixtureAccount`, `createFixtureBoard`, `extractJsessionId`,
  `FixtureAccount`, `FIXTURE_PASSWORD` are all gone; every spec (`auth`, `boards-list`,
  `route-guard`, `theme`) now seeds through `seedAccount()`/`seedBoard()`.
  `e2e/global-setup.ts`'s `/admin/reset` precondition is untouched in mechanism; only its 12-line
  header comment was compressed to 3 (PC-05).
- `boards-list.e2e.spec.ts`'s exact `"ALL BOARDS (2)"` caption assertion (validation/copy per
  D-05) is replaced with a structural link-count assertion — the caption's exact wording is
  already covered by `sidebar.test.tsx`'s composed-story tests (plan 02.1-09/prior work). No
  other assertion across the four spec files targets validation copy, microcopy, or edge-case
  error rendering — `auth`/`route-guard`/`theme`'s assertions are all business-outcome (redirect
  destinations, cookie presence/values, session persistence), kept per D-05.
- Every `test(` body in all four files carries `// Arrange` / `// Act` / `// Assert` comments —
  `theme.e2e.spec.ts`'s single long flow gets a marker at each of its four scenario transitions
  (toggle, reload, sign-out/sign-in, toggle-back), not one set for the whole body. All comment
  blocks across `e2e/` are within PC-05's 3-prose-line limit, including the three that previously
  exceeded it (`theme.e2e.spec.ts`'s 16/5/4-line blocks).

## Decisions Made

- **`e2e/seed.sh`'s constants are `SEED_PASSWORD`/`SEED_DISPLAY_NAME`, not a verbatim
  `FIXTURE_PASSWORD`/`FIXTURE_DISPLAY_NAME` port.** Task 2's own acceptance criteria requires a
  zero-match repo-wide grep for the literal string `FIXTURE_PASSWORD` after `e2e/fixtures.ts` is
  deleted — porting the *value* verbatim (Task 1's instruction) but renaming the *identifier*
  satisfies both requirements without contradiction.
- **`curl`'s `-f` flag is not used in `seed.sh`.** The plan's action text suggests `-f`, but the
  plan's own `<behavior>` block requires a non-2xx response to print its status and body to
  stderr — `-f` suppresses the body on failure, which would satisfy the literal action text but
  not the behavior it exists to produce. Implemented via `curl -w '\n%{http_code}'` and manual
  status parsing instead.
- **The cookie-jar cleanup `trap` uses a double-quoted string.** `trap "rm -f '$jar'" EXIT`
  expands `$jar` immediately at trap-registration time; the plan's own example
  (`trap 'rm -f "$jar"' EXIT`, single-quoted) defers expansion to script `EXIT`, by which point
  `cmd_account`'s `local jar` is out of scope — this produced a real `unbound variable` error the
  first time the script was run against the backend (see Issues Encountered).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Single-quoted cookie-jar cleanup trap referenced an out-of-scope local variable**
- **Found during:** Task 1, first real run of `bash e2e/seed.sh account` against the deployed
  nonprod backend.
- **Issue:** `trap 'rm -f "$jar"' EXIT` (matching the plan's own action-text example, single-
  quoted) defers `$jar`'s expansion to script `EXIT` — by then `cmd_account`'s `local jar` has
  gone out of scope, producing `seed.sh: line 1: jar: unbound variable` under `set -u` even
  though the account had already been created successfully.
- **Fix:** Changed to a double-quoted trap (`trap "rm -f '$jar'" EXIT`), which bakes the jar's
  literal path into the trap command at registration time instead of deferring the expansion.
- **Files modified:** `e2e/seed.sh`.
- **Verification:** Re-ran `bash e2e/seed.sh account` against the real backend — clean exit 0,
  valid JSON on stdout, no trap error.
- **Committed in:** `029daa2` (Task 1 commit)
