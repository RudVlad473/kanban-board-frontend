# Phase 02.1 Plan 01: Board List RSC Tracer Summary

**Rebuilt the sidebar's board-list read as a React Server Component (zod-validated,
session-derived), deleted the Route Handler + TanStack Query stack that fed it, and proved the
new spine with the phase's first composeStories test and a real-backend integration test suite.**

- **Duration:** ~80 min

- **Completed:** 2026-08-21T11:58:00Z

## Accomplishments

- `loadBoards()` (server-only, `verifySession()` → `externalApi.GET` → `boardsSchema.safeParse()`
  → newest-first reversal) replaces `app/api/boards/route.ts` + `useBoards()`/`boardsApi`
  entirely — no Route Handler, no client-side query, anywhere in the board-list read path.
- `BoardSchema`/`boardsSchema` (zod) replace the hand-written `isBoard`/`isBoardArray` guards —
  this phase's first real zod DTO consumer beyond `update-theme.ts`'s narrow `z.enum` usage.
- `Sidebar` is now a plain prop-driven client component (`{ boards, loadFailed }`); its retry
  control calls `router.refresh()` instead of a TanStack Query `refetch()`.
- `app/(dashboard)/layout.tsx` composes `<Suspense fallback={<SidebarSkeleton />}><SidebarBoards />`,
  a local composition-only wrapper — no business logic leaks into `app/`.
- `src/test-utils/factories/board.ts` and `session-record.ts` (D-11) — factory functions with
  `Partial<T>` overrides, not a class needing `new`.
- `sidebar.test.tsx` rewritten as this phase's first `composeStories`/portable-stories test
  (D-08), driven through RED (failing against Task 1's literal story data) then GREEN (factories
  wired in) — the only surviving `vi.mock` calls are the documented `next/link`/`next/navigation`
  environment shims (D-19); the `useBoards` business-logic mock is gone entirely.
- `load-boards.integration.test.ts` (4 passing tests, real backend) recreates every behavior the
  deleted `app/api/boards/route.test.ts` proved (D-21): unauthenticated, session-derived `userId`
  (a second account's board never appears), own-account boards returned, and no upstream-text
  leak on an invalid session.
- `scripts/check-no-route-handlers.mjs` + `handlers:check` (package.json + CI) fail the build if
  any `app/**/route.ts` reappears (D-01/D-05 in the threat register).

## Decisions Made

- **Known open question resolved:** confirmed `newestFirst()`'s `[...boards].reverse()` (in the
  now-deleted `use-boards.ts`) is a pure insertion-order reversal — the backend returns
  creation-order with no timestamp field to sort by instead (per the code's own inline comment
  citing 02-BACKEND-FACTS.md). `load-boards.ts`'s `[...parsed.data].reverse()` is behaviorally
  identical; no deviation from the plan's spec was needed.
- `sidebar.stories.tsx` needed `parameters.nextjs.appDirectory: true` added — `Sidebar` now calls
  `useRouter()` for its retry control, and without that flag the "storybook" Vitest project
  throws "invariant expected app router to be mounted". Matches
  `theme-toggle.stories.tsx`/`sign-in-form.stories.tsx`'s existing precedent; not spelled out in
  the plan text but a direct, obvious consequence of the prop-driven `Sidebar` rewrite.
- `load-boards.integration.test.ts`'s "invalid upstream session" test asserts the call *throws*
  (a `NEXT_REDIRECT` from `externalApi`'s own response middleware forcing a full sign-out) rather
  than resolving to `{status: "error"}` as D-21's prose literally suggested. This is the real,
  already-established, more secure behavior — proven directly against the real backend and
  matching `server-client.integration.test.ts`'s own equivalent test for the identical scenario
  — not a code defect in `load-boards.ts`.

- **Found during:** Task 3 (`load-boards.integration.test.ts` first run against the real backend)

  unrelated to this plan's frontend code.
- **Fix:** Switched to `randomUUID().slice(0, 8)` as the randomizing suffix — the same pattern
  `e2e/boards-list.e2e.spec.ts` already uses successfully — instead of a full UUID.
- **Files modified:** `src/features/boards/server/load-boards.integration.test.ts`
- **Verification:** All 4 integration tests pass against the real backend.
- **Committed in:** `59951d1` (Task 3 commit)

- **Follow-up:** Plan 02.1-02 should re-add these directives once the rule actually targets
