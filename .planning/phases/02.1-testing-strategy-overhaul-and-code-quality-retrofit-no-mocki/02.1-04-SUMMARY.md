# Phase 02.1 Plan 04: Constant-Consolidation Cleanup Summary

**Extended `EXTERNAL_PATH` with sign-in/sign-up/theme/admin-reset members type-checked against
the OpenAPI contract, renamed `boardDetail` to `buildBoardDetailPath`, and grouped four scattered
E2E config exports into one `E2E_CONFIG` object — the three mechanical code-quality items 02-08's
deferred review flagged (D-13/D-14/D-15).**

## Accomplishments

- `EXTERNAL_PATH` (`src/lib/core/api-contract/external-paths.ts`) gained `SIGN_IN`, `SIGN_UP`,
  `USER_THEME`, `ADMIN_RESET` — every backend path this app calls is now declared once, matched
  verbatim against `generated-types.ts`'s `paths` keys, with a co-located test asserting
  no-duplicate-values and every-value-starts-with-slash at runtime, plus a compile-time
  `ExternalPathValue extends keyof paths` assertion that fails `tsc` if a member drifts.
- Every literal call site replaced: `server-client.ts`'s `UNAUTHENTICATED_SCHEMA_PATHS`
  (T-02.1-13's tampering mitigation), `sign-in.ts`, `sign-up.ts`, `update-theme.ts`,
  `e2e/fixtures.ts`, `e2e/global-setup.ts` — plus the unit/integration test files whose literal
  assertions the widened check also catches (see Deviations).
- `scripts/check-routes.mjs` gained `EXTERNAL_PATH_PATTERN`, a second regex run alongside the
  existing `ROUTE_PATH_PATTERN`, each violation naming which declaration file (`ROUTE` vs
  `EXTERNAL_PATH`) the literal belongs in. Proven against a real negative-case probe (`exit 1`,
  cleaned up afterward).
- `boardDetail` renamed to `buildBoardDetailPath` (D-15) — reads correctly at its one call site
  (`href={buildBoardDetailPath(board.id)}`) unlike the noun form. `routes.ts`'s two oversized
  comment blocks (including the pre-existing `PROTECTED_PREFIXES` one, needed for the file-wide
  acceptance criterion) compressed to <=3 prose lines each (PC-05).
- `e2e/test-env.ts` rewritten to export one `E2E_CONFIG` object (`SESSION_SECRET`,
  `EXTERNAL_API_BASE_URL`, `PORT`, `BASE_URL`) following ADR tech/0012's `as const` pattern, not
  `enum` — `BASE_URL` derives from a single module-local `E2E_PORT` constant instead of restating
  the port number. Every consumer updated: `playwright.config.ts`, `e2e/global-setup.ts`,
  `e2e/fixtures.ts`, `e2e/route-guard.e2e.spec.ts` (the only spec reading `E2E_SESSION_SECRET`).

## Decisions Made

- **`ADMIN_RESET` lands in `EXTERNAL_PATH`, not a separate `EXTERNAL_OPS_PATH`.** The plan
  hedged that the admin-reset endpoint was "the likely case" for being absent from the OpenAPI
  contract — checking `generated-types.ts` directly showed `"/admin/reset"` IS a declared `paths`
  key (line 167), so it's a normal member with no need for the fallback object.
- **No `SIGN_OUT` member added.** `sign-out.ts` makes no upstream call at all (only clears this
  app's own cookies), and `"/signout"` is not a key in `generated-types.ts`'s `paths` either —
  there is no call site that would use it. The widened `check-routes.mjs` pattern still guards
  against a future `"/signout"` literal reappearing, even with no current member for it.
