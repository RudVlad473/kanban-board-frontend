# Phase 02.1 Plan 07: UI Primitives — Composed-Story Shallow Coverage Summary

**Button, IconButton, Checkbox, Switch, and TextField now drive their copy/aria-state/disabled/
loading assertions through `composeStories()` against their own sibling `.stories.tsx` files,
discovering and fixing a cross-mechanism DOM-leak bug along the way.**

## Performance

- **Duration:** ~100 min
- **Tasks:** 3
- **Files modified:** 6 (5 `*.test.tsx`, 1 `*.stories.tsx`; no component `.tsx` files touched)

## Accomplishments

- Every one of the five primitives' test files now imports `composeStories` from
  `@storybook/react` (never `@storybook/nextjs-vite`) and drives a subset of its own stories via
  `.run()` for shallow assertions — accessible name/copy, `aria-*` attributes driven by props,
  and disabled/loading rendering.
- Discovered and fixed a genuine cross-mechanism DOM-leak bug: Storybook's portable-stories
  `runStory()` only unmounts a composed story's PREVIOUS render at the start of the NEXT
  `.run()` call, so the last composed-story mount in a test file is never cleaned up by anything
  — and it collides with later `vitest-browser-react` `render()` calls sharing the same
  accessible name (first surfaced as an `IconButton` strict-mode Playwright locator violation).
  Fixed with `afterEach(() => { document.body.innerHTML = ""; })` in all five files.
- Split every mixed Shallow+Deep test (e.g. "renders disabled and suppresses activation on
  click") into a Shallow composed-story test for the rendering assertion and a trimmed Deep
  direct-render test for only the interaction/computed-style/layout assertion — no coverage was
  deleted, only re-homed to the mechanism that actually needs it.
- Discovered empirically that Checkbox's and Switch's interactive `role="checkbox"`/
  `role="switch"` element is a Base UI `<span>`, never a native input/button — `toBeDisabled()`
  fails against it; the correct shallow assertion is `toHaveAttribute("aria-disabled", "true")`.
- Compressed every touched comment block over 3 prose lines to comply with PC-05
  (`checkbox.test.tsx`'s 20-line GC-14 investigation block included) — `button.tsx`,
  `icon-button.tsx`, `checkbox.tsx`, `switch.tsx`, and `text-field.tsx` (the component files
  themselves) are left untouched, confirmed to be plan 02.1-11's explicit scope.

## Decisions Made

- Mixed Shallow+Deep tests were split rather than left whole or duplicated — each assertion now
  lives with the mechanism that actually needs to make it (composed story for rendering, direct
  render for interaction), per the plan's own classification rule.
- `document.body.innerHTML = ""` in `afterEach()` is the fix for the composeStories/
  vitest-browser-react cross-mechanism leak, applied identically to all five files even though
  Button's original leak was invisible (no name collision) — consistency avoids the same bug
  resurfacing the next time someone reuses an accessible name across a Shallow and Deep test.
- Checkbox/Switch's disabled-state shallow assertions use `toHaveAttribute("aria-disabled",
  "true")`, not `toBeDisabled()`, matching the real DOM shape Base UI renders for a `<span>`-based
  role element.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] composeStories `.run()` and vitest-browser-react `render()` leave colliding
DOM mounts across tests in the same file**
- **Found during:** Task 1, first full run of `icon-button.test.tsx` (8 of 48 tests failed with
  Playwright strict-mode "resolved to 2 elements" errors)
- **Issue:** Storybook's portable-stories `runStory()` (traced into
  `storybook/preview-api`'s `chunk-SNLGT2ZI.js`) only unmounts a composed story's previous
  render at the START of the next `.run()` call — the LAST composed-story mount in a file is
  never cleaned up. It coexists silently with `vitest-browser-react` `render()` mounts in later
  tests; when both share an accessible name (IconButton's default label "Show password" appears
  in nearly every test), Playwright's `getByRole` throws a strict-mode violation.
- **Fix:** Added `afterEach(() => { document.body.innerHTML = ""; })` to all five touched test
  files (Button included, even though its own leak never collided on a shared name — same latent
  bug, left unfixed would resurface on the next edit).
- **Files modified:** all five `*.test.tsx` files
- **Verification:** Full re-run of each file's `browser` project suite (48/48, 46/46, 32/32) and
  the whole-project `browser` run (335/335) all pass.
- **Committed in:** `8322c14`, `4fcfd64`, `d9e7fec` (one fix per task's own commit)

**2. [Rule 1 - Bug] `toBeDisabled()` fails against Checkbox/Switch's disabled shallow assertion**
- **Found during:** Task 2, first run of `switch.test.tsx`'s new Disabled shallow test
- **Issue:** `Checkbox.Root`/`Switch.Root`'s visible `role="checkbox"`/`role="switch"` element is
  a `<span>`, not a native input/button — Base UI never sets the DOM `disabled` property on it
  (only its hidden native `<input>` sibling, for Checkbox), so jest-dom's `toBeDisabled()` (which
  checks the real DOM property) reports "not disabled" even though `aria-disabled="true"` and
  `data-disabled` are both present.
- **Fix:** Asserted `toHaveAttribute("aria-disabled", "true")` instead, matching the real
  rendered attribute and the existing GC-14 investigation already documented in `checkbox.tsx`.
- **Files modified:** `src/components/ui/switch/switch.test.tsx` (Checkbox's equivalent test was
  written correctly from the start, informed by this same finding)
- **Verification:** `pnpm exec vitest run --project browser src/components/ui/checkbox
  src/components/ui/switch` — 46/46 pass.
- **Committed in:** `4fcfd64`

**3. [Rule 3 - Blocking] `screen.container` does not exist on `@testing-library/react`'s global
`screen` object**
- **Found during:** Task 3, first run of TextField's Password composed-story shallow test
- **Issue:** `.container` is a property of `render()`'s RETURN value, not of the global `screen`
  singleton `@testing-library/react` exports — using it after `await Password.run()` threw
  `TypeError: Cannot read properties of undefined (reading 'querySelector')`.
- **Fix:** Queried `document.body.querySelector(...)` directly instead.
- **Files modified:** `src/components/ui/text-field/text-field.test.tsx`
- **Verification:** `pnpm exec vitest run --project browser src/components/ui/text-field` —
  32/32 pass.
- **Committed in:** `d9e7fec`
