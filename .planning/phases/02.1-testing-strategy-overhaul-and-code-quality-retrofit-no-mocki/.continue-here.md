# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Isolated-worktree cross-plan gaps aren't caught until the merged-result gate — do NOT trust a single plan's internal verification, or the pre-wave `files_modified` overlap check, as proof a wave is clean.
- [ ] CONSTRAINT: `gsd-tools query worktree.cleanup-wave` unconditionally blocks merging any branch containing whole-file deletions — plans that delete files need a manual `git merge --no-ff` instead.
- [ ] CONSTRAINT: Orphaned `tsserver`/`typingsInstaller` processes pointed at deleted worktree paths accumulate and can OOM-crash a full test run — check for and kill them after every worktree removal, before running the next gate.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Trusting per-plan verification as wave-complete | Each isolated worktree forks from the same base and cannot see its siblings' changes. Wave 3 had 3 real cross-plan gaps invisible to any single plan's own checks: (1) 02.1-04 modified 3 files 02.1-06 had already deleted in its own worktree → modify/delete merge conflict; (2) 02.1-04 and 02.1-03 both edited `server-client.integration.test.ts` in incompatible ways → content merge conflict requiring combining both sides' improvements; (3) 02.1-04's widened `check-routes.mjs` flagged literal paths inside brand-new integration test files 02.1-06 created, which 02.1-04's worktree could never have seen. | blocking | After merging **every** plan in a wave, run the full gate (`pnpm lint && pnpm test && pnpm build && pnpm routes:check && pnpm handlers:check`) on the merged result — not just inside each worktree — before marking the wave done. Treat any failure here as a real cross-plan gap to diagnose and fix, not noise. |
| Trusting `worktree.cleanup-wave` for every merge | The tool's deletion guard (`branch_contains_deletions`) is unconditional with no opt-in flag (confirmed in its own source comments, referencing issues #2852/#3003 as a deferred product decision) — it blocks ANY branch containing a whole-file deletion, even an intentional one core to the plan's purpose. | blocking | Before calling `cleanup-wave`, check `git diff --stat master...worktree-agent-X` for `delete mode` lines. If present, skip the tool and do `git merge --no-ff --no-edit worktree-agent-X -m "merge: bring in X"` directly, resolving any conflicts by hand (read both sides, understand what each agent was trying to fix, combine rather than pick one side blindly). |
| Orphaned language-server processes causing OOM | Every `git worktree remove` leaves the on-disk directory referenced by any editor/LSP process that had indexed files inside it (tsserver, typingsInstaller — each configured `--max-old-space-size=8192`). These accumulate silently across a multi-wave session and directly caused a `FATAL ERROR: Zone Allocation failed - process out of memory` crash during a full `pnpm test` run, and separately made a worktree directory un-removable (`Device or resource busy`). | blocking | After every worktree cleanup, run: `Get-CimInstance Win32_Process -Filter "Name = 'node.exe'" \| Where-Object { $_.CommandLine -like "*worktrees*" }` via PowerShell, and `Stop-Process -Force` any matches, before running the wave's post-merge gate. |
| `check-routes.mjs` / similar glob scripts crash on screenshot dirs | Vitest Browser Mode writes gitignored `__screenshots__/<test-file>.tsx/*.png` failure screenshots — but the directory is literally named e.g. `sidebar.test.tsx`, which a naive `*.{ts,tsx}` glob matches, then `readFileSync` throws `EISDIR`. | advisory | Run `find src app -type d -name "__screenshots__" -exec rm -rf {} +` before `pnpm routes:check` if it crashes with EISDIR. |
| Real backend can go fully unreachable mid-session | The nonprod backend (no mock layer, ADR tech/0018) was confirmed via direct `curl` (not just app-level timeouts) to be completely unresponsive for several minutes during Wave 3. | advisory | If integration tests time out session-wide (not just one flaky file), `curl` the backend directly to confirm before assuming a code regression. Poll on a ~30s interval rather than repeatedly re-running the full test suite (wastes real backend load). |
| `pnpm test` full-suite flakiness under parallel load | A different browser-mode test (or the real-backend integration test) fails on a rotating basis on any given full run, but always passes re-run in isolation. | advisory | Never treat a full-suite failure as a real regression without first re-running just the failing file(s) in isolation. |
| Stale `.git/index.lock` from a slow lint-staged hook | `gsd_run query commit` can report `commit_failed` with output truncated right after `prettier --write`, leaving a stale `.git/index.lock` (especially under memory pressure). | advisory | Confirm no real git process is running (`tasklist //FI "IMAGENAME eq git.exe"`), `rm -f .git/index.lock`, then retry with a direct `git commit -m "..."` instead of the wrapper. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
