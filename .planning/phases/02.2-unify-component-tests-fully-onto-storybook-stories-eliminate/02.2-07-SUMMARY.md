## Decisions Made

- **THEME-02** uses `AuthLayout`'s real signed-out route (`/login`, `/register`, which renders
  `ThemeToggle isAuthenticated={false}`) as the unauthenticated interaction surface, rather than
  the plan's documented fallback of signing in then clearing the browser context's cookies —
  the toggle IS reachable without a session on this app, so the plan's primary mechanism
  applied.
- **THEME-03** captures account B's pre-mutation theme baseline via a direct `fetch` to
  `POST /signup` from inside the e2e spec file (`signUpDirectCapturingTheme`), rather than
  `e2e/seed.ts`'s `seedAccount()`, because `seedAccount()`'s curl-based script (D-07) doesn't
  return the assigned theme and re-signing in as B a second time to read a baseline afterward
  would spend a second UI sign-in on B, exceeding the backend's two-concurrent-session cap
  alongside the account-creation call.
- Every lifetime assertion in `cookie-policy.e2e.spec.ts` converts Playwright's absolute
  `expires` (seconds since epoch) to a relative duration before comparing, with a stated
  tolerance (a day for the ~1-year theme cookie, an hour for the ~7-day session cookie) — never
  compared directly against a raw seconds constant.

## Issues Encountered

- **Worktree had no `node_modules`:** this is a fresh git worktree, so `pnpm install
  --frozen-lockfile` was required before any test/lint command could run (not itself a
  deviation from the plan — infrastructure setup, same category as the `.env.local` copy the
  orchestrator's own instructions already called out).
- **WSL shell toolchain drift:** matching 02.2-05-SUMMARY.md's documented issue, `pnpm` was
  unreachable from a plain non-interactive Bash call; every `pnpm`/`playwright` command was run
  through `zsh -lc '...'` to pick up the corrected Node/pnpm toolchain from `.zshenv`.
- **`pnpm test` flakiness under concurrent sibling-wave load:** the first full-suite run failed
  10 tests, all in files this plan doesn't own (`modal.test.tsx`, `toast.test.tsx`,
  `menu.test.tsx`, `text-field.test.tsx`) — `free -h` showed swap fully exhausted (2.0Gi/2.0Gi),
  consistent with the sibling wave-3 plan (02.2-06, `pnpm test:browser`) running concurrently in
  its own worktree. Re-ran with `pnpm exec vitest run --no-file-parallelism`: 571/571 tests
  passed across all 53 files, confirming resource contention, not a real regression from this
  plan's changes — identical root cause and resolution to 02.2-05's own documented occurrence of
  this same issue.
