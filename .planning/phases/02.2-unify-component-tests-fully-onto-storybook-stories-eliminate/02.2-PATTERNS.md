## Pattern Assignments

### `.run()` → direct render (D-01, D-02, D-03) — applies to all 16 `.run()`-consuming test files

**Analog:** `src/components/layout/sidebar/sidebar.test.tsx` (has both halves already — shallow via
`.run()`, deep via `renderWithProviders`) and `theme-toggle.test.tsx`/`sign-in-form.test.tsx` for the
same split.

**Imports pattern** (`sidebar.test.tsx` lines 1-19, unchanged after rewrite except dropping
`renderWithProviders`):
```tsx
import { composeStories } from "@storybook/react";
import { screen } from "@testing-library/react";
import type { ReactNode } from "react";
import { afterEach, expect, it, vi } from "vitest";
import { userEvent } from "vitest/browser";
import { render } from "vitest-browser-react";   // NEW — replaces render-with-providers import

import { describeForEachDevice } from "@/test-utils/describe-for-each-device";

import { Sidebar } from "./sidebar";
import * as stories from "./sidebar.stories";
```

**Shallow test, BEFORE (sidebar.test.tsx lines 58-66):**
```tsx
it("renders the brand mark, the Boards landmark and Hide Sidebar when expanded", async () => {
    await Expanded.run();
    expect(screen.getByText("kanban")).toBeInTheDocument();
    ...
});
```

**Shallow test, AFTER (Pattern 1, RESEARCH.md "Architecture Patterns" §1 — direct render replaces
`.run()`, `screen` queries stay unchanged since they read from `document`):**
```tsx
it("renders the brand mark, the Boards landmark and Hide Sidebar when expanded", async () => {
    // Act — decorators (flex-height wrapper, QueryProvider via setProjectAnnotations) inherited
    // automatically, same as .run() provided (D-03).
    await render(<Expanded />);

    // Assert
    expect(screen.getByText("kanban")).toBeInTheDocument();
    expect(screen.getByRole("navigation", { name: "Boards" })).toBeInTheDocument();
    expect(screen.getByRole("button", { name: "Hide Sidebar" })).toBeInTheDocument();
});
```

**Deep test, BEFORE (sidebar.test.tsx's own `renderSidebar` helper, lines 47-48):**
```tsx
const renderSidebar = (props: { initialTheme: Theme; children: ReactNode; defaultIsExpanded?: boolean }) =>
    renderWithProviders(<Sidebar {...props} />);
```

**Deep test, AFTER — same shape, `render()` from `vitest-browser-react` directly (no more
provider-wrapping helper needed since `Sidebar` itself, not a raw `<Sidebar/>`, isn't a composed
story here — this file's deep tests already render the real component, not a story, so they only
need the import swap):**
```tsx
const renderSidebar = (props: { initialTheme: Theme; children: ReactNode; defaultIsExpanded?: boolean }) =>
    render(<Sidebar {...props} />);
```
Note: for files whose deep tests render a *story* with overridden args (none currently do, but the
pattern exists per RESEARCH.md Pattern 1's "Overriding args" example), use
`render(<Filled password="overridden" />)` — JSX props merge over the story's own args.

**Cleanup pattern — BEFORE (per-file, e.g. `sign-in-form.test.tsx` lines 33-35):**
```tsx
afterEach(() => {
    document.body.innerHTML = "";
});
```
**AFTER (D-04 — centralize into `vitest.setup.ts`, delete all 11 per-file copies):** see
"Shared Patterns → Centralized cleanup" below. Every rewritten test file simply removes its own
`afterEach` block and the now-unused `afterEach` import (unless the file also does other
`afterEach` work, e.g. `sign-out-button.test.tsx`'s `resetSignOutActionCallCount()` call, which
stays as a file-local `afterEach` alongside the removed cleanup line).

### ESLint: ban `.run()` outside stories (D-06)

**Analog (structure to place the new block near):** `eslint.config.mjs` section 8d
(`no-restricted-syntax`, lines 340-388) for the mechanism; section 8d-2 (`no-restricted-properties`,
lines 390-413) for the file-scoping (`files`/`ignores` on `*.stories.tsx`) convention to copy — but
**not** the rule type itself (Pitfall 2: `no-restricted-properties` cannot express `.run()`'s
dynamically-named object).

**Existing scoping pattern to copy (lines 395-397):**
```js
{
    files: ["**/*.{ts,tsx}"],
    ignores: ["**/*.stories.tsx", "**/*.stories.ts"],
    rules: { /* ... */ },
}
```

**New rule (per RESEARCH.md Pitfall 2's exact selector) — add as its own `no-restricted-syntax`
block with the same file-scoping, distinct from block 8d itself:**
```js
{
    files: ["**/*.{ts,tsx}"],
    ignores: ["**/*.stories.tsx", "**/*.stories.ts"],
    rules: {
        "no-restricted-syntax": [
            "error",
            {
                selector: "CallExpression[callee.type='MemberExpression'][callee.property.name='run']",
                message:
                    "composeStories' .run() is banned (docs/adr/tech/00XX, supersedes tech/0021) — render the composed story directly instead.",
            },
        ],
    },
},
```

**No `play:` in stories (D-05)** — new rule, no direct in-repo analog since 0 violations exist today
(pure forward-enforcement); scope with `files: ["**/*.stories.tsx"]` and a selector on
`Property[key.name='play']` inside a CSF3 story object export.

### e2e extension — cookie assertion migration (D-13/D-14)

**Analog:** `e2e/auth.e2e.spec.ts` AUTH-01 block, lines 12-40 (httpOnly session-cookie assertion via
`context.cookies()`).

**Pattern to extend for redirect/rejection assertions migrating from the deleted integration tests:**
```ts
test.describe("AUTH-XX: sign-in rejects an unknown account", () => {
    test("shows the anti-enumeration message and sets no session cookie", async ({ page, context }) => {
        // Arrange
        await page.goto(ROUTE.SIGN_IN);

        // Act
        await page.getByLabel("Email", { exact: true }).fill("nobody@example.com");
        await page.getByLabel("Password", { exact: true }).fill("WrongPassword123!");
        await page.getByRole("button", { name: "Sign In" }).click();

        // Assert
        await expect(page.getByRole("alert")).toHaveTextContent("Invalid email or password.");
        const cookies = await context.cookies();
        expect(cookies.find((c) => c.name === "session")).toBeUndefined();
    });
});
```
Use `seedAccount()` from `./seed` (already imported in `auth.e2e.spec.ts` line 5) for any test
needing a real existing account, per D-15/e2e-infra reuse guidance.

**Edge-case cookie injection (D-15) — new pattern, external API, no in-repo analog yet:**
```ts
// Source: RESEARCH.md Architecture Patterns §4 / playwright.dev/docs/api/class-browsercontext
await context.addCookies([
    {
        name: "session",
        value: tamperedJwt,
        domain: "localhost",
        path: "/",
        httpOnly: true,
        secure: true,
        sameSite: "Lax",
    },
]);
await page.goto(ROUTE.BOARDS);
await expect(page).toHaveURL(new RegExp(`${ROUTE.SIGN_IN}$`));
```
Cross-check `domain`/`path`/cookie `name` against `src/lib/core/cookies/cookie-registry.ts`'s actual
registered values before writing (RESEARCH.md Security Domain warning — a mismatched `domain`/`path`
silently produces a false-negative "rejection").

## Shared Patterns

### Direct composed-story rendering
**Source:** RESEARCH.md "Architecture Patterns" §1 (external, Storybook's own current docs) +
`sidebar.test.tsx`'s existing deep-test `render()` usage pattern.
**Apply to:** All 16 `.run()`-consuming `*.test.tsx` files.
```tsx
import { render } from "vitest-browser-react";

```

### Centralized `afterEach` cleanup
**Source:** `vitest.setup.ts` (new addition, see Pattern Assignments above).
**Apply to:** All `*.test.tsx` files in the "browser" project — remove each file's own
`document.body.innerHTML = ""` `afterEach` block.

### `@storybook/react` import source (not `@storybook/nextjs-vite`)
**Source:** `sidebar.test.tsx` lines 1-6's own comment; every existing `*.test.tsx` file already
follows this.
**Apply to:** Every rewritten test file — keep `import { composeStories } from "@storybook/react"`
unchanged (RESEARCH.md Pitfall 5 — do not "helpfully" switch this now that direct rendering makes
the split feel less load-bearing; the reason for the split is unchanged).

**Source:** every existing component test file (`sidebar.test.tsx` line 50,
`sign-in-form.test.tsx` line 25, etc.), from `@/test-utils/describe-for-each-device` (ADR tech/0014).
**Apply to:** All component test files — unaffected by this phase, keep wrapping every suite.
