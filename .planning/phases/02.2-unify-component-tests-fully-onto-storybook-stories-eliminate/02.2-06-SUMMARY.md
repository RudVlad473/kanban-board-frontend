## Decisions Made
- **`vi.hoisted()` for `mockRefresh`:** both files' `next/navigation` `vi.mock` factory now calls the imported `createNextNavigationShim`, and Vitest's hoisting-to-top-of-file moved that factory call ahead of the plain `const mockRefresh = vi.fn();` initializer, throwing a hoisting error at collection time. Wrapped as `const mockRefresh = vi.hoisted(() => vi.fn());` — exactly the contingency the plan's Task 2 action text named in advance ("wrap the shared values in `vi.hoisted(...)` rather than inlining the bodies again").
- **`renderSidebar`'s `story` option:** picks whichever composed story stages the closest baseline per test (`Expanded` default, `Collapsed` for the one test that starts already collapsed via `defaultIsExpanded: false`), per D-03's instruction — rather than always rendering `Expanded` and overriding `defaultIsExpanded` by hand, which would produce an identical DOM but not match the plan's explicit story-selection guidance.
- **`children` nested, not passed as a prop:** `renderSidebar` renders `<Story defaultIsExpanded={...}>{children}</Story>` rather than `<Story children={children} .../>` — ESLint's `react/no-children-prop` flagged the prop form; nesting satisfies the rule with no behavior change.
- **`initialTheme` dropped from `renderSidebar`'s override surface:** every deep test already stages `THEME.LIGHT`, identical to `Expanded`'s own story arg, so keeping an always-unused override parameter would have been dead surface (same reasoning plan 02.2-04 applied to `theme-toggle.test.tsx`'s `renderToggle`).

**1. [Rule 3 - Blocking] `react/no-children-prop` ESLint error on `renderSidebar`'s initial prop-based form**
- **Found during:** Task 2 (`pnpm exec eslint` on the rewritten `sidebar.test.tsx`)
- **Issue:** The first `renderSidebar` draft passed `children` as an explicit JSX prop (`<Story children={children} defaultIsExpanded={defaultIsExpanded} />`), which `react/no-children-prop` flags as an error.
- **Fix:** Nested `children` as JSX children instead: `<Story defaultIsExpanded={defaultIsExpanded}>{children}</Story>`. Semantically identical for a component whose `Props` type declares `children: ReactNode`.
- **Files modified:** `src/components/layout/sidebar/sidebar.test.tsx`
- **Verification:** `pnpm exec eslint` exits 0 on the file.
- **Committed in:** `c474f58` (Task 2 commit)

**2. [Rule 3 - Blocking] Hoisting error from a `vi.mock` factory calling an imported helper that references a top-level const**
- **Found during:** Task 2 (`pnpm test:browser` on the rewritten files)
- **Issue:** `vi.mock("next/navigation", () => createNextNavigationShim({ pathname: ROUTE.BOARDS, refresh: mockRefresh }))` threw Vitest's own "There was an error when mocking a module... make sure there are no top level variables inside" error at collection time in both files, since `vi.mock` hoists to the top of the file, ahead of the plain `const mockRefresh = vi.fn();` initializer.
- **Fix:** Wrapped the shared value: `const mockRefresh = vi.hoisted(() => vi.fn());` — this is the exact contingency the plan's own Task 2 action text named ("If a factory nevertheless throws a cannot-access-before-initialization error at collection time, wrap the shared values in `vi.hoisted(...)`").
- **Files modified:** `src/features/boards/components/board-list.test.tsx`, `src/components/layout/sidebar/sidebar.test.tsx`
- **Verification:** `pnpm test:browser` passes both files (and the whole `browser` project, 20/20 files, 360/360 tests).
- **Committed in:** `c474f58` (Task 2 commit)
