**Mock-free `session.test.ts`, two new real-backend e2e specs (forced sign-out + cross-account board isolation), and a new ADR-justified Route Handler that fixes a genuine production redirect-loop bug the old mock never could have caught — closing D-13, D-14, and D-15.**

## Accomplishments

- Rewrote `src/lib/server/session.test.ts` mock-free, driving every JWT rejection path directly through `createSessionService(secret).verifyToken(token)` — no `next/headers` mock, no in-memory cookie jar.
- **Discovered and fixed a real production bug** (not a test artifact): `server-client.ts`'s `onResponse` middleware called `session.destroy()` from a Suspense-streamed Server Component render context, where Next.js forbids cookie mutation. The cookie survived, the redirect fired, and `proxy.ts`'s local JWT check immediately bounced the browser back — an infinite `/boards` ⇄ `/login` redirect loop that the deleted `next/headers` mock's fake cookie jar could never have surfaced, because it had no real Next.js request-scope restrictions.
- Implemented the user-approved fix, recorded as `docs/adr/tech/0026-force-sign-out-via-route-handler.md`: a new `app/api/session/force-sign-out/route.ts` Route Handler — the one narrow, ADR-justified exception to `docs/adr/tech/0019`'s project-wide Route Handler ban — legally destroys the session cookie and redirects, closing the loop.
- Added `e2e/session-bridge.e2e.spec.ts` (SESSION-01 forced sign-out, SESSION-02 session rotation) and extended `e2e/boards-list.e2e.spec.ts` with BOARD-02 cross-account isolation, all against the real deployed nonprod backend.
- Deleted both remaining `next/headers`-mocking integration tests (`server-client.integration.test.ts`, `load-boards.integration.test.ts`). Zero `vi.mock("next/headers"` occurrences remain anywhere in the repository — **D-13 is complete**.
- Drive-by: renamed `loadBoards()` to `fetchBoards()` (and its file/type), and documented the `fetch<Noun>()` RSC-read naming convention in `CONVENTIONS.md` ahead of Phase 2's remaining plans.
- Full `pnpm test` (559/559) and `pnpm exec playwright test --project e2e` (26/26) both green, run multiple times for confidence.

## Decisions Made

- **ADR tech/0026** (already recorded by the orchestrator before this dispatch): forced sign-out clears the session cookie via a Route Handler, not inline during RSC render. Chosen over (a) middleware doing its own upstream liveness check on every navigation (unconditional latency cost), (b) a client-triggered Server Action (heavier, visible flash), and (c) accept-and-defer (ships a known user-facing redirect loop). Implemented exactly as specified.
- Split the ADR fix into two commits (Route Handler + registry + build-gate exemption; then the `server-client.ts` change), per the resume instructions' suggested shape — each is independently coherent and buildable.
- `check-no-route-handlers.mjs` gained a real allow-list mechanism (a `Set` of exempt relative paths) rather than a blanket carve-out, so any *future* accidental Route Handler still fails the build.

## Discrimination Check (SESSION-01's own acceptance criteria)

Run once, by hand, during this task's execution, per the plan's mandated sanity check that a redirect alone proves nothing:

1. **WRONG secret:** Minted the forged token with `"DISCRIMINATION-CHECK-WRONG-SECRET-do-not-commit"` instead of `E2E_CONFIG.SESSION_SECRET`, ran SESSION-01 alone. Result: **test failed** at the cookie-absence assertion — `proxy.ts`'s local `verifyToken()` rejected the token before the request ever reached `app/(dashboard)/layout.tsx`, so it redirected to `/login` but the (invalid) session cookie was **never cleared**, because `server-client.ts`'s `onResponse` middleware — the code actually under test — never ran at all.
2. **CORRECT secret** (the actual, committed test): `verifyToken()` accepts the token locally (`proxy.ts` lets the request through), the bridged upstream call to the real nonprod backend is genuinely refused (dead `jsessionId`), `onResponse` redirects to `ROUTE.FORCE_SIGN_OUT`, and that Route Handler **genuinely destroys the session cookie** before its own redirect to `/login`. Result: **test passed**, cookie confirmed absent via `context.cookies()`.

This proves the correct-secret run's cookie-absence assertion is not vacuous: a redirect that never reaches the real forced-sign-out code path (wrong secret) leaves the cookie present, while the real path (correct secret) genuinely clears it.
