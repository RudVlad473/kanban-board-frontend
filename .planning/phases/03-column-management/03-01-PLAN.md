Create `scripts/probe-column-backend.mjs` as a manual Node ESM script modelled on
`scripts/probe-board-backend.mjs`. Reuse that file's account/cookie helpers and its
`signInCounts` guard unchanged — the backend caps an account at two concurrent sessions, so sign in
exactly once per throwaway account and reuse the `JSESSIONID`.

Read the base URL from `process.env.EXTERNAL_API_BASE_URL` and exit non-zero with the same operator
message `probe-board-backend.mjs` prints when it is unset. Never print the URL or any credential.

Add a **reachability preflight** as the script's first action: `POST /signup` with a throwaway
account. If it answers `500` with a problem-detail whose `detail` mentions the JDBC connection pool,
print `probe-column-backend: nonprod DATABASE is down (app layer up) — halting; this is not a code
defect` and `process.exit(2)`. This is the loud halt `03-RESEARCH.md` § "Recommended plan sequencing"
asks for, so an executor never reads a 500 as a bug in this phase's code.

Then seed one board and four columns named `Alpha`, `Bravo`, `Charlie`, `Delta` by four **sequential**
`POST /boards/{boardId}/columns` calls (never parallel — `02-BACKEND-FACTS.md` P5 makes creation
order the source of `position`). Every request carries `?userId=<the signed-in account id>` and the
`JSESSIONID` cookie.

Implement each probe as its own function that prints a labelled block:

- **R1** — `PATCH /boards/{boardId}/columns/{columnId}/reorder` moving index `0` (`Alpha`) with body
  `{ version, targetPosition: 2 }`, then `GET /boards/{boardId}/full`. Print the resulting name order.
  `B,C,A,D` means `targetPosition` is the final index; `B,A,C,D` means insert-before.
- **R2** — from the same `GET .../full`, print every column's `id`, `name`, `position` and `version`
  next to the values captured before R1, so a version bump on a merely-shifted column is visible.
- **R3** — replay R1's exact PATCH body (now-stale `version`). Print status and the problem-detail
  `code`; the expectation to confirm or refute is `409` / `OPTIMISTIC_LOCK_CONFLICT`.
- **R4** — two PATCHes: `targetPosition: 99`, and `targetPosition` equal to the column's own current
  position. Print status, problem-detail `code`, and the column's `version` after each, so a no-op
  that still burns a version is visible.
- **R5** — `POST /boards/{boardId}/columns` with `{ name: "Alpha" }` (a name already on the board).
  Print status and problem-detail `code`; the branch to confirm is `DUPLICATE_RESOURCE`.
- **R6** — `POST /boards/{boardId}/columns/{columnId}` (`SaveTaskRequestDTO`, `{ title }`) to put one
  task into `Bravo`, then `DELETE` `Bravo`, then `GET .../full`. Print whether `Bravo` and its task
  are gone and the remaining columns' `position` values. Then delete a **middle** column of what
  remains and re-read, printing positions again so contiguous-vs-sparse renumbering is visible.
- **R7** — `DELETE` an already-deleted column id. Print status and problem-detail `code`.

Every probe must print its own raw status codes and JSON, not an interpretation, so Task 2 records
observations rather than conclusions. Wrap the whole run in a `try`/`finally` that prints the
throwaway account's email and board id at the end, so nonprod rows are traceable.

Do not add the script to any `package.json` script entry, any workflow file, or any test glob.
