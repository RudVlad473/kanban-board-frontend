## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-23 | Tampering | `toColumnDotToken`'s returned class name | low | mitigate | The three utility literals are declared whole in `model.ts` and indexed by `position % 3`; no class name is assembled from a backend value, so a hostile `position` can only select one of three known constants. Plan 03-04's Test 1 pins the mapping. |
| T-03-24 | Information Disclosure | column name rendered in the header | low | mitigate | The name is rendered as text content, never as markup or as an attribute that could be interpreted, and React escapes it. The header adds no `dangerouslySetInnerHTML` and no `title`/`aria-label` built by string concatenation from a backend value. |
| T-03-25 | Denial of Service | a pathological column name breaking the 280px layout | low | mitigate | The name element carries `truncate` and the count element does not shrink, so a long or wide-glyph name cannot push the count out of the header or widen the row. The backend caps the name at 32 characters (`02-BACKEND-FACTS.md` P6), so the case is bounded rather than open-ended. Test 4 asserts it. |
| T-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs nothing. `03-RESEARCH.md` § Package Legitimacy Audit is the phase's audit table; every entry is **OK/Approved** with `postinstall: null`, none `[ASSUMED]`/`[SUS]`/`[SLOP]`, so no blocking legitimacy checkpoint is required. |

**Canon-referral (not minted as prohibitions):** cross-site scripting through a rendered column name
is canon — covered by React's own escaping, `/gsd-secure-phase`, and the eslint security rules; no
bespoke prohibition is minted for it.
