<objective>
Close the two defects the 03-10 checkpoint found in the running application: a reorder that does not
survive a reload, and a keyboard move that scrolls a neighbouring column out of sight.

Purpose: plan 03-10's write path is correct and proven — the probe's `targetPosition` semantics were
encoded faithfully, the backend stores the new order, and only the moved column's version is bumped.
What was never exercised is the READ. Every automated gate passed while COLUMN-03's own success
criterion — "the new order persists across a reload" — was failing, because fixtures are authored in
creation order, where array index and `position` are the same number. The bug lives exactly in the
gap between those two being equal and being related.

That is also why this plan is separate rather than a patch: the defect is a missing derivation on a
path 03-10 did not own, and the test that closes it is a fixture shape no existing test uses. Folding
it into a finished plan would bury a general lesson — that a field is not an ordering until something
orders by it — inside a plan about drag and drop.

Output: a board that reads back in the order the user left it, a keyboard move that keeps its
neighbours on screen, and a regression test whose fixture would have failed before this plan.
</objective>
