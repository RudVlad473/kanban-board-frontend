Create a **scratch, uncommitted** Storybook story that mounts the smallest possible horizontal
sortable list built from the three installed packages: a `DndContext` with an explicit `id`, sensors
configured as `MouseSensor` (activation constraint `{ distance: 8 }`) + `TouchSensor`
(`{ delay: 200, tolerance: 8 }`) + `KeyboardSensor` (`coordinateGetter: sortableKeyboardCoordinates`),
a `SortableContext` using `horizontalListSortingStrategy`, and five `useSortable` items each rendering
a `<button>` carrying `attributes` + `listeners` + `setActivatorNodeRef`, styled with
`CSS.Transform.toString(transform)` and `transition` from `@dnd-kit/utilities`. Give each item a
sibling `<button>` that is NOT a drag handle, so Pitfall 5 (a click on a sibling control starting a
drag) is observable. Reproduce the real board's shape closely enough for the auto-scroll question to
be meaningful: a horizontal `overflow-x-auto` row with enough fixed-width children to exceed the
frame, each child its own vertical scroll region.

`MouseSensor` + `TouchSensor` are used deliberately in place of `PointerSensor`: `PointerSensor`
carries no interactive-element guard at all in this version, and the harness cannot be relied on to
synthesise the pointer events it needs (`03-RESEARCH.md` Pitfalls 4 and 5).

Start Storybook (`pnpm storybook`) and drive the story headless through the `mcp__playwright__*`
tools. Observe and record five things:

1. **Mount under React 19.2** — the story renders with no runtime error and no console error.
2. **Keyboard path** — focusing an item's handle and pressing the lift key, then an arrow key, then
   the lift key again, actually reorders the list; pressing escape mid-lift returns it to its
   original index. Record which keys dnd-kit accepts for the lift by trying both the space bar and
   the enter key: this phase's decision D-06 **keeps dnd-kit's default `keyboardCodes`** rather than
   narrowing them, so both are expected to lift, and `03-RESEARCH.md` Open Question 3's
   recommendation to narrow to space-only is **superseded** and must not be implemented.
3. **Pointer path** — a low-level `page.mouse` press, a multi-step move, and a release reorders the
   list. Record the number of intermediate move steps needed before dnd-kit registers a drag.
4. **Sibling-control safety** — a plain click on the non-handle sibling button fires that button and
   starts no drag.
5. **Auto-scroll in nested scroll containers** — drag an item toward the row's right edge and record
   whether the horizontal row auto-scrolls, and whether a child's own vertical scroll region
   interferes. This is `03-RESEARCH.md` Open Question 4.

claiming it was confirmed — record the mechanism as verified-by-source (the module-scope
`useUniqueId` counter in `@dnd-kit/utilities`) and the fix as required-by-construction.
