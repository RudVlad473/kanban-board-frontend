pointer path; this expands it to every way a user can actually move a task.

scrollable ancestor, which for a task is its own column body rather than the horizontal column row.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| keyboard input → move requests | An unguarded step-per-keystroke path would issue a request per keypress, each carrying a version the previous one invalidated |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-32 | Denial of Service | one request per completed move | high | mitigate | Intermediate arrow steps stay local; a browser case asserts the call-log length is exactly one after a multi-step keyboard move, which is the assertion that would catch a per-keystroke regression |
| T-04-06 | Tampering | stale-version writes from rapid stepping | high | mitigate | Because only the completed move sends a request, no move ever carries a version a sibling request already invalidated |
| T-04-33 | Denial of Service | shared keyboard sensor mismeasuring | medium | mitigate | The narrowing is branched on the declared type and both directions are asserted, so a task drag cannot silently measure the wrong scroll container |
| T-04-05 | Information Disclosure | announcement strings | low | mitigate | Every announcement is authored and interpolates only the task title and column name the user can already see |
| T-04-SC | Tampering | package-manager installs | low | accept | This plan installs nothing; the drag modifiers package was concluded NOT NEEDED in the phase-3 spike and must not be added on the strength of that finding. `04-RESEARCH.md` § Package Legitimacy Audit records zero packages added |
</threat_model>
