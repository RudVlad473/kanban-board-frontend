## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|----------------------|
| Repeating a stale memory as current fact | A memory said local e2e wipes the shared backend; false since `5f325f8`. Cost a wrong recommendation that fenced off a capability the user wanted. | blocking | Before repeating a recalled claim, open the code it names. A memory that cites a commit is falsifiable — check whether a later commit changed it. |
| Reporting CI green before verifying it | Recurring across sessions. This session it was verified independently and matched, but the habit is what protects it. | blocking | `gh run watch <id> --exit-status`, then read back each job's conclusion from `gh run view --json jobs`. A queued or running job means "not yet". |
| Trusting a green suite that never ran the tests | `--project unit` on `scripts/*.unit.test.mjs` exits 1 with "No test files found" — and the inverse, an empty result from a crashed check, looks identical to a clean run. | advisory | Check the exit code AND the reported test count, not just the absence of failures. |
| A four-step setup ritual documented in prose | `next typegen` was documented and still skipped by two separate Phase 4 executors, who then reported the resulting phantom lint errors as a real regression. | advisory | Now collapsed into `pnpm setup:worktree`. Prefer one command over a documented list; prefer a mechanism over a document. |
| Per-invocation `pnpm run` in a hook | Three `pnpm run` calls cost 8514 ms, ~80% of it dispatch overhead — the shape that earns a reflexive `--no-verify`. | advisory | One process invoking `node scripts/*.mjs` directly. `scripts/secrets.sh precommit` is the worked example (8514 ms → 1337 ms). |
