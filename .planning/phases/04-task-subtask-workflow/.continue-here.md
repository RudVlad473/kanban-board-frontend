# BLOCKING CONSTRAINTS — Read Before Anything Else

> Each was discovered through actual failure this session. Acknowledge each before proceeding.

- [ ] CONSTRAINT: a scoped-green test run proves almost nothing — three fix agents each ran their own files green while `pnpm test` was broken by a file none of them owned. Run the FULL suite before believing a change is safe.
- [ ] CONSTRAINT: verify a premise before briefing an agent on it — I told an agent "create-column already closes on submit"; the citation was about *rename*. It stopped and checked rather than building on it, which is the only reason a false consistency argument did not ship.
- [ ] CONSTRAINT: never `cd <dir>; git ...` — with a `Read()` deny rule configured the permission layer cannot resolve the cwd and prompts every time. Use `git -C <dir>`.
- [ ] CONSTRAINT: `pkill -f <pattern>` matches the shell running it and kills the whole call (exit 144). Kill by PID from `pgrep -af`.
- [ ] CONSTRAINT: a permission rule added to `.claude/settings.local.json` does NOT apply to the session that wrote it — `permissions` is read at startup.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|----------------------|
| Trusting a scoped test run | Three agents ran their own files green; `app/global-error.test.tsx` and `app/(dashboard)/error.test.tsx` failed to import with `ReferenceError: process is not defined` after the `next/link` conversion. In no agent's path, so all three were green while the suite was red. | blocking | Run `pnpm test` (full) before committing anything that changes an import shared across route groups. |
| Briefing an agent on an unverified premise | An investigation's citation about `useRenameColumn` was read as being about `useCreateColumn`, turning "make two hooks match a third" into an unnoticed product-policy reversal. | blocking | Re-read the cited line yourself before it becomes a brief. Instruct agents to stop if the premise is false — this one did, and that is what saved it. |
| Reading `pnpm lint` errors inside a worktree | A hand-added worktree under the repo root put 710 errors from a second checkout into `pnpm lint`. Fixed by ignoring `.worktrees/**`, but a worktree elsewhere would recur. | advisory | Check the error paths belong to the checkout you are in before diagnosing. |
| Skipping `next typegen` in a fresh worktree | All three worktrees produced 3 phantom `PageProps`/`LayoutProps` errors, reading as a real regression in a file nobody touched. | advisory | `pnpm exec next typegen` then `git checkout -- next-env.d.ts` in every new worktree. |
| Appending `echo "EXIT=$?"` after the command you care about | The wrapper reports the echo's status, so a failed `gh run watch` was reported as exit 0. | advisory | Let the command you care about be the last thing in the script. |
