## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|----------------------|
| Trusting a guard that has never been made to fail | `import-x/no-cycle` was added to replace the `ui → ui` ban. Its first config reported a real `button ⇄ icon-button` cycle as clean, exit 0: the rule parses imports itself and, with no `import-x/parsers` mapping, walked an empty graph. The repo's existing `import/parsers` comes from `eslint-config-next` and does not reach the `import-x` namespace. | blocking | Create the violating condition, watch the guard fail, then remove it and watch it pass. Never accept a green run as evidence a new guard works. ADR tech/0031 says to re-falsify after any change to eslint section 7c. |
| Asserting visibility with `toBeVisible()` | jest-dom checks `display`, `visibility`, `opacity` and `hidden` — never `clip` or size. Tailwind's `sr-only` sets none of those, so six existing assertions claimed visible text that was 1×1px and clipped, and all 1214 browser tests stayed green while doing it. | blocking | Assert measured geometry (`getBoundingClientRect`) when the claim is that something is *seen*. Reserve `toBeVisible()` for presence. |
| Compressing a comment instead of deleting it | `comments:check` caps a comment at 3 prose lines and never asks whether it should exist, so every candidate got squeezed and kept. Result: 21.8% of non-test source is comments and 579 unresolvable planning tokens across 188 files. | blocking | A comment is a luxury, not a default. Never cite a token the reader cannot resolve from the repo — `docs/adr/*` is fine, `D-21` / `T-02-47` / `S-09` / `*-SUMMARY.md` are not. Passing the length gate is not evidence the comment should exist. |
| Re-recording a baseline to make a suite green | The visual baselines were recorded from the same rendering that carries the N-2 line-height defect, so they lock it in. A `--update-snapshots` run will always "fix" a failure. | advisory | Look at the recorded image before accepting it. Re-record only when you can say what changed and why it is correct. |
| Driving the app on top of a seeded session | The backend caps concurrent sessions at 2. Signing in through the browser while a `seed.sh account` session exists evicts one, and the app then fails writes that look like regressions. It cost a false "create is broken" diagnosis. | advisory | Register a fresh account through the UI for live checks, or reuse the seeded session's cookie. Known issue: `.planning/todos/pending/2026-08-27-boards-create-e2e-401s-when-its-seed-session-is-evicted.md`. |
