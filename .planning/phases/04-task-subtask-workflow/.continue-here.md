# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each was discovered through actual failure.

- [ ] CONSTRAINT: **One working tree, one agent.** File-disjoint agents still share one git index
      and one pre-commit hook, so each hook run sweeps the others' half-finished work and agents
      "resolve" it with `--no-verify`. Two `comments:check` failures reached this branch that way.
      Structural mitigation: worktrees are FORCED OFF for this phase (see below), so dispatch
      strictly one executor at a time. Never accept `--no-verify`.
- [ ] CONSTRAINT: **A single green suite run is not evidence.** Failures here are load-dependent;
      a standalone file run does not reproduce them, and two agents have already reported green
      while wrong. Structural mitigation: the ORCHESTRATOR re-runs the full `pnpm test` three
      consecutive times plus all 12 gates after every plan, and confirms CI with
      `gh run view <id>` — an executor's own claim is never the sign-off.

**Do not proceed until both boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Concurrent agents in one checkout | File-disjoint agents share the git index and pre-commit hook and bypass it to get their own files in | blocking | One worktree per agent, or strict serialisation. Worktrees are forced off here, so serialise. `--no-verify` is never the answer |
| Single-run green | Load-dependent failures pass when a suite runs once or a file runs alone | blocking | Three consecutive full `pnpm test` runs from the orchestrator, all exit codes reported, plus CI |
| `dispatch-isolation` force is clobbered by any later plain read | `--force-isolation none` persists, but ANY subsequent plain `dispatch-isolation` call re-resolves the host capability and overwrites it back to `harness-worktree`, re-arming the Agent isolation guard. Reading it back to confirm is what destroys it | advisory | Force isolation as the LAST gsd-tools call before `Agent()`. Never read it back. On a guard rejection, just re-force and retry |
| zsh eats `:check` as a history modifier | `pnpm $s:check` in a loop reported exit 1 for all 9 gate scripts that actually pass — read as "every gate is broken" | advisory | Always brace it: `pnpm "${s}:check"`. Verify a suspicious all-fail by running one gate directly |
| Trusting an executor's own green claim | 04-17's agent reported one full run; its truncated final message also looked like a stall while the work had in fact completed and pushed | advisory | Spot-check git + SUMMARY on disk before believing either success OR failure, then re-verify gates independently |
| Trusting a reviewer's findings | A Gemini 3.1 Pro review returned 4 findings; 2 were false, and the "critical" one would have replaced a working `next/cache` export in 3 Server Actions | advisory | Check every finding against `tsc`, the suite, or the running app before changing code |
| Stale LSP diagnostics | Diagnostics reported missing exports and type errors; `tsc --noEmit` exited 0 both times | advisory | Believe the compiler, not the editor, especially right after a rename or refactor |
