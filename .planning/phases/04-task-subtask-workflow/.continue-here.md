## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Partial-suite green | `pnpm test:unit` passes while `browser`/`storybook` projects are red | blocking | Run `pnpm test` (all three projects) before any completion claim; `pnpm verify` before push |
| Pipeline-masked exit code | `cmd \| tail -3` makes the wrapper report tail's status, hiding a real failure | blocking | Let the command you care about be last, or read the structured result separately |
| Base UI `render`-prop disabling | `isDisabled` on `<Menu.Trigger render={<IconButton/>}/>` is dropped by the prop merge — the guard looks right in source and does nothing | advisory | Disable at `<Menu.Root isDisabled>`; assert `toBeDisabled()` in an e2e, never by reading the source |

## Critical Anti-Patterns (do NOT repeat these)

- [ANTI-PATTERN]: Claiming green from `pnpm test:unit` → run `pnpm test`, then `pnpm verify`.
- [ANTI-PATTERN]: Branching JSX on a value `refresh()` re-resolves (e.g. `openBoardId`) → React sees
  a changed element type and remounts the subtree, closing open modals. Keep one stable tree shape.
- [ANTI-PATTERN]: Trusting `HydrationBoundary` for SSR markup → it hydrates in an effect, so the
  server render sees an empty cache. Pass the server value down as `initialData` too.
- [ANTI-PATTERN]: Creating reviewer worktrees before committing the `E2E_PORT` override → the
  worktree lacks it and every reviewer silently shares one server.
