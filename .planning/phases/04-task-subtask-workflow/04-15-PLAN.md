<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → create actions | Callable over the wire with an arbitrary payload, including an arbitrarily long initial-subtask array |
| client-orchestrated fan-out → backend | N sequential writes from one user intent, each independently failable |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | create action payloads | high | mitigate | `.safeParse` after the session check on all three actions; the title bounds are the promoted core-ring schemas rather than restated per action |
| T-04-02 | Elevation of Privilege | user id in the upstream query | high | mitigate | Read only from the verified session record on all three actions, asserted by grep and by the absence of any argument path to it |
| T-04-04 | Denial of Service | unbounded initial-subtask fan-out | medium | mitigate | The array is capped at the action boundary at the same limit the board's initial-column names use; a unit case asserts an over-cap payload is rejected before any call is made |
| T-04-05 | Information Disclosure | inline create-failure copy | medium | mitigate | The action returns bare discriminants; the inline message is authored, so no upstream text reaches the modal |
| T-04-36 | Tampering | double submission | medium | mitigate | The submit control is in its loading state and both dismissal guards are held while the post is in flight, so one user intent cannot become two tasks |
| T-04-SC | Tampering | package-manager installs | low | accept | This plan installs nothing; `04-RESEARCH.md` § Package Legitimacy Audit records zero packages added by this phase |
