<objective>
Turn the passive gate on for the whole `e2e` project, record what is already true, and measure what
it costs.

Purpose: 04-23 built the mechanism and proved it on four cases. A harness only the harness uses
catches nothing. This plan does the three things that make it real — makes every spec pick the gate
up, makes forgetting to impossible rather than merely discouraged, and puts the wall-clock price of
both in front of a human with a number attached.

tolerances re-derived from a real measurement, a backlog inventory of what the scan found, and a
green CI run with all of it in.

<decisions_this_plan_makes>
**D-G — the rollout is enforced by ESLint, not by convention.** An `auto` fixture only fires for a
test built from the extended `test` object, so the passive coverage is exactly as good as the next
author remembering which module to import from. That is the manual step this whole revision exists
to remove. A `no-restricted-imports` entry scoped to e2e spec files, banning the `test` and `expect`
named imports from `@playwright/test` and naming the fixture module in its message, converts
"remember to" into "cannot forget": `pnpm lint` is a `VERIFY_STEPS` entry and a `ci.yml` step, so a
spec that opts out fails before it can be pushed.

Use the `@typescript-eslint` variant of the rule with type imports allowed, so a
`import type { Page } from "@playwright/test"` line keeps working — 16 of the 23 specs need it, and
moving those type imports into the fixture module would turn it into a barrel for Playwright's types
for no gain.

**D-H — `full-app.e2e.spec.ts` is excluded, by name.** It is the only spec outside the `e2e`
project: `playwright.config.ts` carves it out with `testIgnore` and its own header records why (six
runs on 2026-09-03, intermittent, cause unidentified, deliberately not in CI). Nothing runs it on a
schedule, so its baseline would rot, and the first person to run `pnpm test:smoke` in a month would
meet a red they did not cause on a spec that is already the repo's flakiest. Excluding it costs one
named file in one config block, greppable and auditable.

What would make D-H false: `smoke` joining CI. At that point it should join the rollout in the same
change.

**D-I — the cost is measured and taken to a human, not absorbed silently.** 04-23's D-B keeps the
gate out of `VERIFY_STEPS` because the `e2e` project already runs it, and that stays mechanically
true here — no `ci.yml` command changes, so `gates:check` is unaffected. But the COST changed
category: 04-23 added four tests, this plan adds an accessibility scan and a score read to
seventy-three. `docs/review-brief.md` records the `e2e` project at ~2 minutes and `pnpm verify` at
~7 minutes; `CLAUDE.md` records a measured `pnpm verify` total of 5m14s. Task 2 measures the delta
against both, task 3 re-runs the full pipeline, and the checkpoint puts the number in front of the
developer with the two narrowing levers named. Neither lever is applied unilaterally — both narrow
coverage, which is a decision, not an optimisation.

**D-J — nothing under `src/` or `app/` is touched.** The baseline recording will surface real
accessibility findings on surfaces nobody has scanned this way. Fixing them is not this plan's job
and would smuggle unreviewed product changes into an infrastructure commit. They are inventoried as
one pending todo with counts per rule, and the baseline file itself is the detailed record. Asserted
by a clean `git diff` over those two trees.
</decisions_this_plan_makes>

|----------|-------------|
| a new spec file → the passive gate | An `auto` fixture only fires for tests built from the extended `test` object, so a spec importing Playwright's own is silently ungated |
