<objective>
Build a reusable Playwright quality-verification fixture layer that catches the subtle
visual/timing regressions static end-state screenshots miss — component thrashing, flicker, layout
shift during an interaction, and optimistic-update timing — and prove it against the running
application.

Purpose: this repo's existing test tiers each have a blind spot. The `visual` project screenshots
Storybook primitives at rest (ADR tech/0008), the `e2e` project asserts settled end states, and the
`browser` Vitest project cannot reproduce a mechanism that only exists in a real compositor. Three
of this phase's own defects lived exactly in that gap and were each found by ad-hoc video review or
a hand-written one-off observer. This plan turns that ad-hoc work into infrastructure.

Output: `e2e/quality-fixtures.ts` (six exports) and `e2e/quality-fixtures.e2e.spec.ts` (the
harness's own standing self-test), plus one new devDependency.
</objective>

<decisions_this_plan_makes>
Four scope questions the planning was asked to answer rather than leave ambiguous. Each is
implemented below and recorded permanently by plan 04-24's ADR.

**D-A — the validation spec is PERMANENT, not a `zz-` probe.** `e2e/quality-fixtures.e2e.spec.ts`
joins the `e2e` project for good. A fixture layer with no standing test is the exact failure this
harness exists to catch: an in-page `MutationObserver`, a `PerformanceObserver` entry type, or an
axe API that silently stops installing makes every spec that uses it pass. The repo already treats
instrument vacuity as first-class — `boards-switch.e2e.spec.ts` carries explicit "a silently
uninstalled observer must fail here, not pass everything" guards — and this spec IS those guards for
the shared layer. Cost accepted: three more seeded accounts and roughly 30-60s on a 75-test suite.
The `zz-` convention (`docs/review-brief.md`) still applies to one-off probes built ON this harness,
including plan 04-24's react-scan probe and the board-delete investigation this unblocks.

**D-B — NO new `VERIFY_STEPS` entry and NO new `ci.yml` step.** Because of D-A the spec matches the
`e2e` project's `**/*.e2e.spec.ts` glob, so `pnpm verify`'s existing `pnpm exec playwright test
--project e2e` step and `ci.yml`'s `e2e` job already run it. Adding a step would either duplicate
that or land as an `uncovered-step` violation in `gates:check`. The observable consequence, asserted
below: `VERIFY_STEPS` stays at 20 and `pnpm gates:check` exits 0 unchanged.

**D-C — `layoutShiftTracker` is scoped to an INTERACTION window, never a page load.** `start()` is
called after the route has settled, the interaction runs, then `getScore()` is read. A cumulative
score measured across the initial load would be a different instrument answering a question ADR
tech/0008's `visual` project already owns for the design system, and would be dominated by font and
image settling that says nothing about a transition. The self-test enforces this by calling
`start()` only after the board route is visible.

**D-D — `react-scan` is deferred to plan 04-24 and stays opt-in.** It is not one of the five
fixtures and, unlike them, needs a network fetch from a CDN at fixture-setup time. Putting that in a
spec that D-A makes a standing pre-push and CI gate would add an unpkg.com dependency to every push.
04-24 adds it as an opt-in fixture proved by a throwaway probe, never exercised by the standing spec.
</decisions_this_plan_makes>
