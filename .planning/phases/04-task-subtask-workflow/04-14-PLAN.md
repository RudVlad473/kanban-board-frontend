<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| optimistic UI state → what the user believes is saved | A revert without a signal makes the screen and the server disagree with no notice |
| backend conflict response → client branch | The only place the app learns another writer won |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06 | Tampering | stale-version move (lost update) | high | mitigate | The version is required on the move, the conflict discriminant reverts and toasts, and the action re-reads so the screen stops showing data known to be wrong |
| T-04-34 | Repudiation | silent rollback | high | mitigate | A single browser case asserts revert and toast together rather than separately, so a revert path that loses its signal fails rather than passing two independent tests |
| T-04-35 | Tampering | per-action conflict special-casing | medium | mitigate | A differing problem-detail code is added to the shared mapper, never switched on inside a hook, so two actions cannot drift on what a conflict means |
| T-04-05 | Information Disclosure | conflict toast copy | medium | mitigate | The action returns bare discriminants; the toast strings are authored, so no upstream text can reach the UI |
| T-04-SC | Tampering | package-manager installs | low | accept | This plan installs nothing; `04-RESEARCH.md` § Package Legitimacy Audit records zero packages added by this phase |
</threat_model>
