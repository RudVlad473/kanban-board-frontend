  <behavior>
    - `Modal.Root` with `isOpen` false renders nothing into the accessibility tree; the underlying
      page content remains reachable.
    - With `isOpen` true, a control with role `dialog` is present and its accessible name is the
      `Modal.Title` text.
    - While open, Tab cycles only among the focusable elements inside the dialog — focus does not
      escape to the page behind it.
    - Escape invokes `onOpenChange` with false, and focus returns to the element that was focused
      before the dialog opened.
    - Clicking the backdrop invokes `onOpenChange` with false by default, and does not when
      `isDismissableOnBackdropClick` is false.
    - `Modal.Description`, when present, is exposed as the dialog's accessible description.
  </behavior>

    (`Dialog.Root`, `Dialog.Trigger`, `Dialog.Portal`, `Dialog.Backdrop`, `Dialog.Popup`,
    `Dialog.Title`, `Dialog.Description`, `Dialog.Close`). Focus trapping, scroll locking, escape

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| overlay content → page behind it | A dialog that fails to contain focus or scroll leaks interaction into content the user believes is blocked |
| design source → implemented tokens | Values measured from a PDF render, rather than read from a text layer, can be wrong in a way no automated test detects |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-27 | Denial of Service | Modal focus trap or scroll lock failing, stranding a keyboard user | medium | mitigate | Focus trapping, scroll locking and focus restoration delegated to Base UI's Dialog (D-15); the test asserts both the trap wrap and the restoration, and the checkpoint has the human verify it by keyboard with the mouse untouched |
| T-01-25 | Spoofing | Dialog presented without an accessible name, so a screen-reader user cannot tell what it is asking | medium | mitigate | The accessible name is derived from `Modal.Title` through Base UI's Dialog wiring; axe runs at error severity across every Modal story |
| T-01-28 | Tampering | Measured radius and shadow values silently wrong, since no text-layer source exists to assert against | low | mitigate | Values and their source frames are recorded in `01-04-SUMMARY.md`; the checkpoint puts them in front of a human beside the original design, which is the only check available for a value with no machine-readable source |
</threat_model>
