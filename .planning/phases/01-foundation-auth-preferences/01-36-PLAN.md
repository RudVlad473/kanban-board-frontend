<objective>
Turn on the three-ring boundaries policy and move the whole pure ring of `src/lib/` into
`src/lib/core/`, subdivided by concern, updating every importer. This is round-4 gap closure
GC-25 (three-ring split) and GC-28 (mechanical enforcement) for the pure ring only; the server and
client rings and the feature-local moves are plan 01-37, and the documentation is plan 01-38.

Purpose: `src/lib/` is a flat catch-all that mixes pure helpers with server-only secret-holding
infrastructure and browser-coupled infra, with nothing in the folder structure signalling which is
which — the exact ambiguity that produced the 01-33 Storybook stub. The three-ring split makes the
platform coupling of every module structural and lint-enforced rather than a convention a reader has
to know.

Purpose of doing the eslint change first, in this plan's tracer: the flat `lib` element pattern is
`src/lib/*`, which matches only direct children of `src/lib/` and does not match a nested file like
`src/lib/core/styling/cn.ts` (verified with micromatch during planning). `boundaries/dependencies`
is configured `default: "disallow"`, so the instant a file is moved into a subfolder the old flat
element stops capturing it and every importer's `feature -> lib` edge resolves its `to` element to
nothing and is disallowed — `pnpm lint` fails mid-move. Landing the three `**` element patterns
before any file moves means the ring each file lands in is already a recognised element, so lint
stays green at every step.

Output: the eslint config carries three `lib-*` element types with GC-25's ring directionality, and
`src/lib/core/` holds the pure ring in four concern subfolders with every importer repointed.
</objective>
