## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Windows `cleanup-wave` worktree removal always reports `ok:false` | `gsd-tools worktree.cleanup-wave` merges the branch into `master` correctly (verify with `git log`), but its internal `git worktree remove` step reliably fails with `fatal: '<path>' is not a working tree`. | advisory | After every `cleanup-wave` call, unconditionally `rm -rf .claude/worktrees/agent-<id>` (retry once for a transient Windows file lock), `git worktree prune`, `git branch -D worktree-agent-<id>`. Don't be alarmed by `ok:false` — check `git log --oneline -3` to confirm the merge commit landed. |
| `gsd-tools worktree.cleanup-wave` also blocks (`cleanup_blocked` / `branch_contains_deletions`) when a plan's own worktree branch legitimately deletes files | Wave 6's Task 3 intentionally retired `src/components/ui/harness-probe/` — the tool's safety guard against accidental deletions has no override flag, so the merge must be done manually (`git merge --no-ff <branch>`) after verifying via `git diff --stat master <branch>` that the deletion is exactly what the plan describes and nothing else. | advisory | Before merging manually, diff-stat the branch against master and confirm every deletion matches the plan's stated intent. |
| A screenshot judged "wrong" at a glance may not actually be wrong | This session spent 7 CI round-trips (~2 hours) chasing a "CI shows the wrong font" bug based on an initial casual visual read of a screenshot. A later rigorous, zoomed-in, side-by-side pixel comparison against a known-different reference (Arial) showed the very first, unfixed CI baseline already matched a confirmed-correct font — the bug likely never existed in the rendered output, only in my judgment of it. | blocking | Before declaring any UI/visual output "wrong" or "fixed" — especially before spending further iteration cycles (CI dispatches, code changes) chasing it — do a rigorous zoomed-in crop comparison against a known reference, AND get explicit user sign-off before proceeding further. Never trust a casual glance at a small, low-contrast region of a screenshot. See `feedback_ui_change_signoff` and `feedback_post_run_learnings_review` auto-memories (saved this session as a direct result). |
| Node's `-e`/`require` path resolution disagrees with Git Bash's `/tmp` | A `node -e` script reading `/tmp/foo` resolves to literal `C:\tmp\foo`, NOT the location Git Bash's own `/tmp` maps to (`C:\Users\<user>\AppData\Local\Temp\...`) — silently ENOENTs or reads a stale/wrong file. Contributed to the font-race confusion above (a hash comparison against the wrong path family produced misleading "still broken" results). | advisory | For cross-tool file verification on Windows, use the PowerShell tool's `Get-FileHash` (not Bash+Node mixed), or stay within one tool consistently for a given file path. See `.planning/WINDOWS.md` id 3. |

**Do not proceed past the blocking row above without internalizing it** — the next wave (01-07) will produce new component screenshots; don't repeat the same fast-judgment mistake.
