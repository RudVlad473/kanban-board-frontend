  accessibility; hand-roll only where Base UI has no equivalent (D-15).

  `const` arrow form per D-26k, no `React.FC` per D-26l.
- Variant, size and state styling through `class-variance-authority` (D-26u). Sizes `sm`/`md`/`lg`
  on every size-varying primitive (D-18).
- Accepts and forwards `className`, merged through `cn` so a consumer class wins over a
  conflicting base class (D-26v).
- Boolean props take an `is`/`has` prefix, event handlers an `on` prefix, matching Base UI's own
  naming (D-26s).
- Consumes semantic tokens only, never primitive-tier tokens (D-02).
- Definition of done is the component plus a Vitest Browser Mode test exercising click, keyboard
  and error/disabled-state rendering, plus Storybook stories covering default, hover, focus,
  disabled and (for form primitives) error (D-16, D-20). Stories are visual-only — no play
  functions; interaction assertions live only in the test file (D-25).
- Visual-regression baselines are appended to `visual/primitives.visual.spec.ts` as the stories
  ship (D-22), in both light and dark scope.

<decisions>
**Button label type size — a gap UI-SPEC left open, resolved here.** The source design system's
button label is Bold 15 px, which is `font-heading-m` — a style UI-SPEC deliberately excluded from
this phase to stay inside its four-distinct-sizes budget, noting a later phase should reintroduce
it against that phase's own budget. Rather than smuggle a fifth size back in, all three Button
sizes use the declared `font-body-m` composite token (Bold 12 px / 15 px line height) and express
size variation through height and horizontal padding: `sm` 32 px, `md` 40 px, `lg` 48 px. Flagged
for the plan 01-09 visual checkpoint, where a human compares the rendered button against the
Figma frame and can call for `font-heading-m` to be reintroduced if 12 px reads too small.
</decisions>
