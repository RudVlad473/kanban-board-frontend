<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user keystrokes → TextField value | The first primitive in the project that holds user-entered text, including passwords in plan 01-12 |
| primitive props → rendered DOM attributes | Label, description and error strings become accessible names and descriptions |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Information Disclosure | TextField holding a password value | high | mitigate | The primitive holds the value in React state only — it must not write to `localStorage`, `sessionStorage`, `document.cookie`, or any logging call. `type="password"` renders a masked input, and the visibility toggle is a caller-supplied `trailing` node so the primitive never itself decides to reveal a secret |
| T-01-25 | Spoofing | A form control rendered without an accessible name, letting a user act on a control they cannot identify | medium | mitigate | `label` is a required prop on both primitives, so an unlabelled control is a type error; axe runs at error severity across every story and would fail the build on a violation |
| T-01-26 | Tampering | Error message text rendered into the accessible description | low | accept | Error strings originate in this codebase and in Zod schema messages authored in plan 01-12, not from server or user input; React escapes text content, so there is no markup-injection path |
</threat_model>
