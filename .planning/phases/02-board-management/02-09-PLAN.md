<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> client-side collapse state | Collapse state is purely presentational and carries no authority; nothing server-side reads it |
| RSC props -> client components | Board names cross from `loadBoards()` into `BoardList` as plain props; the values are this same user's own data, already session-scoped server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-39 | Information Disclosure | Collapse state written to a cookie or a browser storage area | low | mitigate | DEFAULTS.md C-009 locks this to ephemeral React state. Persisting it would add a client-writable value with no validation path — small in itself, but the same class as the theme cookie's tampering surface. Task 2 asserts mechanically that the cookie string is unchanged across a toggle and greps the file for any storage or cookie write. |
| T-02-40 | Denial of Service | Sidebar collapsed with no reachable expand control | medium | mitigate | Losing the only route to the board list would functionally lock a user out of every board. Task 2's behavior block requires a `Show Sidebar` control in the collapsed state and asserts keyboard reachability for both controls; Task 3 proves the round trip end to end against the real backend. |
| T-02-41 | Information Disclosure | Board names rendered over the content in the mobile overlay treatment | low | accept | The overlay renders the same user's own board names already visible in the expanded desktop panel; no additional data crosses any boundary. |
| T-02-42 | Elevation of Privilege | `BoardList` moving into the boards feature folder pulling a server-only module into the browser bundle | medium | mitigate | `BoardList` imports only the `Board` type from `schemas.ts`, `buildBoardDetailPath`, and `cn` — nothing from `src/lib/server/`. `eslint-plugin-boundaries` permits `feature -> lib-core` but not `lib-core -> lib-server`, and `pnpm build` fails on any `server-only` import reaching a client bundle. Asserted by Task 2's `pnpm build` criterion. |
</threat_model>
