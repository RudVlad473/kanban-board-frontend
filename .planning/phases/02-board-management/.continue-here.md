## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| GSD's worktree cleanup-wave verb can race the harness's own worktree teardown | On wave 13's merge, `gsd_run query worktree.cleanup-wave` reported `worktree_remove_failed` ("is not a working tree") — the merge itself had already landed correctly, but the harness (Claude Code's own `isolation="worktree"` cleanup) had already removed the git worktree registration before GSD's own removal step ran, leaving a stray directory of build artifacts (`.next`, `next-env.d.ts`) with no `.git` file. | advisory | Before treating a `cleanup-wave` failure as data loss: check `git log --oneline` on the reported branch name first (`git show-ref --verify --quiet refs/heads/<branch>`) — if the commits are there and `git worktree list` / HEAD already show a `chore: merge executor worktree (...)` commit, the merge succeeded and only the final directory removal failed. Just `git branch -d <branch>` (safe, already merged) and `rm -rf` the stray directory; do not re-attempt `cleanup-wave` or assume the merge needs redoing. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
