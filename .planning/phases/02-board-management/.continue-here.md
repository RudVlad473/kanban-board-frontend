# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Never `rm -rf node_modules/.cache` while a live dev/Storybook server for the same worktree is running — it corrupts the manager-bundle serving irrecoverably (404s on the server's own JS bundles) until a fresh process restart. If cache clearing is needed, stop the server first, clear, then start fresh.
- [ ] CONSTRAINT: Test-fixture accounts on the real nonprod backend cap out at 2 concurrent sessions. Any setup script that both signs up AND separately signs in to do authenticated setup work (e.g. seeding data) burns both slots before a human ever gets one — reuse the signup response's own session cookie for follow-up authenticated calls instead of opening a fresh `/signin`. The orchestrator's own pre-inspection sign-in (before handing a checkpoint to the human) also consumes a slot — budget for this when creating checkpoint accounts, and know that **signing out via the UI does NOT free the slot** (the upstream sign-out endpoint is broken/500s; only the frontend cookie clears, documented in `sign-out.ts`'s own comment).
- [ ] CONSTRAINT: Screenshots taken via Playwright of `position: fixed` content portaled inside a nested iframe (e.g. Toast stories viewed through the outer Storybook manager URL) are unreliable — can render blank even when the content is genuinely visible. Cross-check with `getComputedStyle`/`getBoundingClientRect` via `browser_evaluate`, not screenshot pixels alone, before concluding something is broken.
- [ ] CONSTRAINT: A full-page reload and a client-side (`next/link`) navigation are visually indistinguishable in a screenshot or DOM snapshot — the URL changes, the active state updates, everything *looks* right either way. The only way to verify real client-side navigation is inspecting actual network requests during the click (`browser_network_requests`) — expect only an RSC payload fetch (`?_rsc=...`), no full document request, no re-fetch of data the outer layout already loaded.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Copying an `<a href>` pattern from one context to another without reconsidering fit | `sidebar.tsx` copied the auth-forms' plain `<a>` (legitimate there — one-time transition, `next/link` throws `process is not defined` in Vitest Browser Mode) onto board-row navigation, the app's most frequent interaction, causing full-page reloads on every click | blocking | `no-restricted-syntax` now bans every raw `<a>` JSX element regardless of href shape (commit `a205d32` on branch `worktree-agent-aff6e55fca144924a`) — any future raw `<a>` requires an explicit `// eslint-disable-next-line no-restricted-syntax` with a written justification, forcing a conscious choice instead of silent copy-paste |
| `@next/next/no-html-link-for-pages` gives false confidence | This rule only fires on a static string-literal `href` (e.g. `href="/x"`) — it silently passes on `href={someFunction(id)}`, exactly the shape that shipped the bug above | advisory | Verified directly with a probe file before and after the fix — see the `no-restricted-syntax` rule above, which is shape-agnostic |

_Both rows apply — do not remove._
