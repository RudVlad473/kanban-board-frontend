  </read_first>
  <behavior>
    - `resolveWithinRoot({ root, pathname: "/index.html" })` returns the joined path inside root
    - `resolveWithinRoot({ root, pathname: "/assets/nested/app.js" })` returns the joined path inside root
    - `resolveWithinRoot({ root, pathname: "/../package.json" })` returns `null`
    - `resolveWithinRoot({ root, pathname: "/..%2fpackage.json" })` returns `null` (the check runs after `decodeURIComponent`, not before)
    - `resolveWithinRoot({ root, pathname: "/a/../../package.json" })` returns `null`
    - `resolveWithinRoot({ root, pathname: "/" })` returns root itself (so the existing directory-index branch still fires)
    - A sibling directory whose name merely starts with root's name (`<root>-other/secret.txt`) returns `null` — the check compares against root plus a trailing separator, not a bare string prefix
  </behavior>
  <action>
    Extract the path resolution out of the request handler into a named exported arrow function
    `resolveWithinRoot` taking a single destructured object argument (`{ root, pathname }`) and
    returning `string | null`. It must: `decodeURIComponent` the pathname first; build the
    candidate with `path.resolve(root, "." + pathname)` so a leading `/` cannot be treated as an
    absolute path that discards root; then confirm containment by testing that the resolved
    candidate is strictly equal to `path.resolve(root)` OR starts with `path.resolve(root) +
    path.sep`. Return `null` on any failure, including a `decodeURIComponent` throw on a malformed
    percent-escape.

    In the request handler, call `resolveWithinRoot` and, when it returns `null`, take the existing
    404 branch (`res.writeHead(404, ...)` / `res.end("Not found")`) rather than adding a new status
    code — the existing branch already returns the same body for a missing file, so a probe cannot
    distinguish "outside root" from "does not exist". Keep the directory-index step, the MIME
    lookup and the 200 branch exactly as they are, operating on the returned path.

    Write `scripts/serve-static.unit.test.mjs` first (red), importing `resolveWithinRoot` from
    `./serve-static.mjs` and covering every bullet in the behavior block. Use the repository root
    as `root` in the fixtures so `package.json` is a real file one level up. The module must not
    start listening on import for the test to be usable — guard the `server.listen(port)` call so
    it only runs when the module is executed directly, using
    `process.argv[1]` compared against `fileURLToPath(import.meta.url)`.
  </action>
  <verify>

  </verify>
