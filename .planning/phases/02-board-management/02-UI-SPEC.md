# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Sources:** `docs/kanban-task-management-web-app.pdf` (Frontend Mentor "Kanban Task Management
Web App" design export, 73 pages — canonical visual system) cross-referenced against this
project's own already-implemented Phase 1 design-token pipeline
(`src/styles/tokens.css`, generated via DTCG → Style Dictionary → Tailwind v4, plan 01-04) and
existing primitives (`src/components/ui/{button,icon-button,modal,text-field,dropdown,checkbox,
switch}`). Per this phase's brief: **CONTEXT.md governs product/UX decisions** (D-01..D-15,
cascade-delete, optimistic updates); **the PDF governs the visual system** (colors, type scale,
spacing, component anatomy). Where the two genuinely conflict on a *placement* mechanic (see
Interaction Notes below), CONTEXT.md's explicit decision wins and the PDF's visual anatomy is
transplanted onto the CONTEXT.md-decided location.

**Critical: tokens.css is already the implemented, tested, visual-regression-baselined design
system** — built in Phase 1 directly from this same PDF. This UI-SPEC does **not** re-derive new
color/spacing/typography values; it declares the already-locked token values as this phase's
contract and documents where the token pipeline made a deliberate adjustment from the PDF's raw
values (contrast fixes, single-hover-shade-per-theme instead of the PDF's per-theme hover swap).
Every new component this phase builds (Sidebar, BoardCard, AddBoardModal, EditBoardModal,
DeleteBoardConfirm, Toast) must consume these existing tokens/primitives, not invent new ones.

## Spacing Scale

Declared values — this project's own already-implemented 4px-base scale
(`src/styles/tokens.css`, `--space-*`), reused verbatim (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Icon-to-label gaps, popup item inset (`Dropdown.Content` `p-1`) |
| `--space-2` | 8px | Compact element spacing, board-card internal gap |
| `--space-3` | 12px | TextField/Dropdown trigger vertical padding (`py-3`) — the one non-template tier, already load-bearing on every Phase 1 form primitive; kept, not renegotiated |
| `--space-4` | 16px | Default element spacing, modal padding (mobile), sidebar row horizontal padding |
| `--space-6` | 24px | Section padding, modal padding (tablet+), board-view column gutters |
| `--space-8` | 32px | Layout gaps between major regions |
| `--space-12` | 48px | Major section breaks |
| `--space-16` | 64px | Page-level spacing |

Exceptions:
- **44×44px minimum touch target** on every icon-only control (`IconButton` `size-11`/`size-12`,
  already implemented) — applies to this phase's kebab-menu trigger and collapse/expand toggle.
- Sidebar width: **300px** at desktop/tablet (`--breakpoint-md`/`--breakpoint-lg`, 768px/1440px
  already declared), collapsing to a 0-width hidden state below the sidebar's own "Hide Sidebar"
  toggle (DEFAULTS.md C-009, plain `useState`, non-persisted). Below `--breakpoint-md` (375px
  mobile), the sidebar is not a persistent column — see Interaction Notes → Responsive Sidebar.

## Typography

This project's already-implemented 5-token type scale (`src/styles/tokens.css`) mapped onto the
template's 4 semantic roles. All values verified against both the PDF's Design System page 1 and
the live token file — they match exactly (Plus Jakarta Sans, Bold = 700, Medium = 500):

| Role | Token | Size | Weight | Line Height | Usage this phase |
|------|-------|------|--------|-------------|-------------------|
| Display | `heading-xl` | 24px | 700 | 30px | Board title in the dashboard header (e.g. "Platform Launch") |
| Heading | `heading-l` | 18px | 700 | 23px | Modal titles — "Add New Board", "Edit Board", "Delete this board?" (`Modal.Title`, already wired to this token) |
| Label | `body-m` | 12px | 700 | 15px | Field labels ("Board Name", "Columns"), board-card meta ("X of Y subtasks"), button/menu-item text |
| Label (caption) | `heading-s` | 12px | 700 | 15px, +2.4px tracking | ALL-CAPS section captions — sidebar "ALL BOARDS (N)", column headers "TODO (N)"/"DOING (N)"/"DONE (N)" |
| Body | `body-l` | 13px | 500 | 23px | Default paragraph/description text, sidebar board-row names, delete-confirmation body copy, input values |

Weight is applied via `[font-weight:var(--font-weight-{token})]` arbitrary-property syntax
project-wide (documented Tailwind v4 namespace-collision workaround, `button.tsx` comment) — new
components this phase adds must follow the same pattern, not a bare `font-bold`/`font-medium`
utility.

## Color

This project's already-implemented semantic token layer (`src/styles/tokens.css`), themed via a
single `.dark` class-scope override — not per-component light/dark branching:

| Role | Token(s) | Light | Dark | Usage |
|------|----------|-------|------|-------|
| Dominant (60%) | `--color-bg-app` | `#F4F7FD` | `#20212C` | Page background, board-view canvas |
| Secondary (30%) | `--color-bg-surface` | `#FFFFFF` | `#2B2C37` | Sidebar panel, dashboard header bar, modal panels, board-card surfaces |
| Accent (10%) | `--color-bg-primary` / `--color-bg-primary-hover` | `#635FC7` / `#5854BE` | `#635FC7` / `#5854BE` | See reserved-for list below — same hover shade in both themes (deliberate Phase 1 simplification vs. the PDF's per-theme hover swap, see Deviations) |
| Destructive | `--color-bg-danger` / `--color-bg-danger-hover` | `#C93F3C` / `#B23632` | `#C93F3C` / `#B23632` | Destructive actions only — see reserved-for list below |

Accent reserved for (explicit list — never "all interactive elements"):
1. Selected/active sidebar board row — full `bg-bg-primary` fill, white (`text-on-primary`) label (PDF: the highlighted "Platform Launch" row).
2. The "+ Create New Board" sidebar link — accent-colored icon + text on the transparent sidebar surface (not a filled button).
3. Primary CTA buttons — "Create New Board" (Add Board modal submit), "Save Changes" (Edit Board modal submit), "Create your first board" (zero-boards empty-state CTA), "+ Add New Task" (header — inherited from Phase 3/4 scope but visually present per PDF).
4. `Dropdown`'s active-item checkmark (`Select.ItemIndicator`, already `text-bg-primary`) and every primitive's `focus-visible` ring (`--color-ring-focus`, already global).

Destructive reserved for:
1. "Delete Board" text inside the sidebar row's kebab/overflow menu (D-07).
2. "Delete this board?" confirmation modal — title text color and the "Delete" button's fill (`Button variant="destructive"`, already implemented).
3. Error/rollback toast accents (icon or left-border) for board-mutation failures — D-04 (partial column-creation failure), D-09 (delete failure), D-15 (rename rollback).

**Deviations from the PDF's raw palette (already baked into `tokens.css`, not to be
re-derived):** the PDF's raw destructive red (`#EA5555` idle / `#FF9898` hover) and raw
accent-hover (`#A8A4FF`, PDF's light-mode-only hover shade) were adjusted during Phase 1's token
generation to `#C93F3C`/`#B23632` (contrast-adjusted red-500/red-300) and a single
`#5854BE` hover (used in both themes, replacing the PDF's separate per-theme hover swap). These
are load-bearing, already visual-regression-baselined values — this phase's new components must
match `tokens.css`, not the PDF's raw swatches, if the two ever disagree.

## Interaction Notes (non-template, phase-specific)

**Sidebar kebab-menu placement diverges from the PDF — CONTEXT.md D-07 governs.** The PDF's own
mockups (pages 24/30 of the source PDF) place the "Edit Board"/"Delete Board" menu in the
dashboard **header**'s "⋮" trigger (top-right, beside "+ Add New Task"). CONTEXT.md's D-07
explicitly locks this menu onto **each sidebar board row** instead (alongside a "Rename" action
the PDF's header-kebab doesn't have, since PDF's header-kebab only ever acts on the
currently-open board). Per this brief's precedence rule (CONTEXT.md governs product/UX
placement; the PDF governs visual anatomy), build the menu using the PDF's exact `Dropdown`
visual anatomy — popup surface, item padding/typography, destructive-red "Delete Board" text —
but trigger it from an `IconButton` (kebab glyph) on each `BoardCard` row, not from the header.
See 02-RESEARCH.md Common Pitfall 3 for the `Dropdown`-as-action-menu composition requirement
(reset the underlying `Select` value after each action; never let "Delete"/"Edit"/"Rename"
render as a persisted selection).

**Responsive sidebar.** The PDF's mobile breakpoint (375px) mockups do not show a persistent
sidebar column at all — the header's board title becomes a dropdown-style control (board name +
chevron) that, when tapped, opens the "ALL BOARDS (N)" list plus the light/dark toggle as a
floating overlay panel anchored below the header, dismissing on selection. DEFAULTS.md C-009
only locks the desktop collapse/expand mechanic (plain `useState`, non-persisted) and does not
address mobile explicitly — recommend the same overlay-panel pattern below
`--breakpoint-md` (768px), consistent with ADR tech/0010's mobile-review precedent already cited
in `dropdown.tsx`'s and `modal.tsx`'s own comments. Flagged as a recommendation, not a locked
decision — no CONTEXT.md item constrains mobile sidebar behavior for this phase.

**Toast placement/behavior.** No new visual tokens needed — `Toast.Root` should reuse
`bg-bg-surface`/`shadow-lg`/`rounded-lg` (the same panel treatment `Modal.Content` already uses)
with a colored left-border or leading icon in `--color-bg-danger` for error toasts (D-04/D-09)
and no accent color for the rollback-only case unless it's also an error. Base UI's
`Toast.Viewport` renders its own `aria-live="polite"` region (RESEARCH.md, verified) — no
additional ARIA wiring needed.
