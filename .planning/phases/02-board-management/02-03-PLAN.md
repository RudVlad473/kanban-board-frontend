and reshape both from loose exported functions into factory-namespaced objects, matching the
`createSessionService` shape `session.ts` already uses (PC-03). The rename from `session-cookie.ts`

distinction: `session.ts` manages this app's own cookie via `next/headers`, while this module
parses an arbitrary external `Response`.

paths, so this must land first.

caller repointed.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external Kanban backend → Next.js server | `upstreamCookie.extract` parses an arbitrary `Set-Cookie` header off the backend's raw `Response` — untrusted, attacker-influenceable text if the backend were ever compromised or spoofed |
| browser → Next.js server | The client-writable `theme` cookie is read back by `themeCookie.read()` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-08 | Spoofing | `upstreamCookie.toHeader` in `src/lib/server/cookies/upstream-cookie.ts` | high | mitigate | The produced header must remain byte-identical (`JSESSIONID=<value>`). A drift silently un-authenticates every board/theme call against the real backend. Task 2's test pins the exact string and Task 3's `pnpm test:e2e` proves it against live nonprod (GC-18, T-01-48/50/52). |
| T-02-09 | Tampering | `upstreamCookie.extract` parsing loop | medium | mitigate | The relocated loop keeps using `response.headers.getSetCookie()` (array form) rather than the comma-joined `headers.get("set-cookie")`, so an `Expires` attribute's own comma cannot split one entry into two and yield a truncated credential. Asserted by the moved test and pinned by Task 2's acceptance criteria. |
| T-02-10 | Tampering | `themeCookie.read` validation | medium | mitigate | The relocated read still passes the raw value through `isTheme` and returns `null` for anything else, so a tampered non-httpOnly `theme` cookie cannot inject an arbitrary string into the root layout's class computation (T-01-35). |
| T-02-11 | Elevation of Privilege | `src/lib/server/cookies/**` reaching a client bundle | high | mitigate | Both new files open with `import "server-only"`, and `eslint-plugin-boundaries`' existing `src/lib/server/**` glob already classifies the new subfolder as `lib-server`, so a `lib-client` or `lib-core` import of it fails lint. Task 3's `pnpm lint` and `pnpm exec tsc --noEmit` are the gate. |
| T-02-12 | Information Disclosure | Theme cookie surviving a sign-out | low | mitigate | Deliberately deferred to plan 02-04 (folded todo FT-01); `themeCookie.clear()` is created here so that plan needs no further change to this module. |
</threat_model>
