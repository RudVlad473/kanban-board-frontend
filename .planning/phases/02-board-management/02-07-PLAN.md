    consequence — the kebab trigger's glyph would flicker to "Delete Board" after the menu closes,
    and a checkmark would appear beside whichever action was last clicked. Read that pitfall and
    `src/components/ui/dropdown/dropdown.tsx` to confirm.

    **Fact 2 — that same pitfall contains an error.** It states "Base UI does not currently ship a
    public `Menu` primitive alongside `Select`/`Dialog`/`Field`". That is incorrect for the
    installed version. Confirm with `ls node_modules/@base-ui/react/menu` and
    `head -25 node_modules/@base-ui/react/menu/index.d.ts`: version 1.7.0 ships a `menu/` entry
    point exporting `Menu.Root`, `Menu.Trigger`, `Menu.Portal`, `Menu.Positioner`, `Menu.Popup`,
    `Menu.Item`, `Menu.Group`, `Menu.GroupLabel`, `Menu.Arrow` and `Menu.Backdrop`, plus sibling
    `context-menu/` and `menubar/` entry points.

    Either way, D-07's substantive decision — the menu's placement on each sidebar row alongside
    Rename — is honoured exactly. Only the parenthetical mechanism is in question. Task 3 of this
    plan is written for Option A; choosing Option B drops Task 3 and moves the kebab composition
    into plan 02-12 using `Dropdown`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application code → toast render surface | Whatever string a caller passes becomes visible page content; if a caller ever forwarded a raw backend body it would surface here |
| browser DOM → portalled toast/menu popups | Both primitives render outside the React tree's DOM position via portals, so focus and announcement behaviour is not inherited from the trigger's ancestors |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-27 | Information Disclosure | `Toast.Description` content | medium | mitigate | The primitive renders whatever string it is given, so the control lives at every call site: every consumer plan (02-10, 02-12, 02-13) uses the UI-SPEC Copywriting Contract's authored copy and never forwards a raw upstream error body. Recorded as this plan's prohibition and re-asserted in each consuming plan's acceptance criteria. |
| T-02-28 | Tampering | Board and column names rendered inside a toast or menu item | low | accept | React escapes JSX text nodes by default and no `dangerouslySetInnerHTML` exists anywhere in this codebase; neither primitive introduces raw HTML rendering. No new control needed — but plans must not introduce one. |
| T-02-29 | Denial of Service | Module-scope `createToastManager()` singleton shared across concurrent SSR requests | medium | mitigate | Task 2 forbids the module-scope manager outright and relies on `Toast.Provider`'s per-tree store reached through `useToastManager()`, the same reasoning `query-client.tsx` already documents for `QueryClient`. Asserted by a grep in Task 2's acceptance criteria. |
| T-02-30 | Elevation of Privilege | Destructive action reachable without confirmation from the overflow menu | high | mitigate | `Menu.Item` is a plain action trigger with no confirmation of its own by design. The confirmation is the consumer's responsibility and is specified in plan 02-13 (D-06's confirm modal). This plan's `isDestructive` variant is visual only and must not be mistaken for a safety control. |
| T-02-31 | Repudiation | Toast announcement not reaching assistive technology | medium | mitigate | Base UI's `Toast.Viewport` renders its own polite live region; Task 2's behavior block requires asserting what the installed version actually renders rather than assuming, and `pnpm test:a11y` gates the stories. |
