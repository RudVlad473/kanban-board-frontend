<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `PUT /api/boards/{boardId}` | Untrusted `boardId` path segment and request body, including a `version` a caller could set to anything |
| Next.js server → external Kanban backend | The server-derived `userId`, the caller's `boardId` and the optimistic-locking `version` all cross here |
| TanStack Query cache → rendered UI | The optimistic patch makes the UI temporarily assert something the server has not yet confirmed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-55 | Elevation of Privilege | `userId` on the PUT handler | critical | mitigate | `userId` comes from `verifySession()` only; the handler forwards the caller's `boardId` with the session's own id, so the backend's single-owner scoping refuses another user's board (02-BACKEND-FACTS.md P7). Task 1 includes a test sending a client `userId` and asserting the session's own id reached upstream. |
| T-02-56 | Tampering | Stale-`version` overwrite on rename | high | mitigate | Backend-enforced optimistic locking via the required `version` field is the actual control; this frontend's job is to always send the current one from the cache entry being renamed, which Task 1's schema requires at this app's own boundary and Task 2's behaviour pins. A stale version is rejected rather than silently applied. |
| T-02-57 | Tampering | Unvalidated request body reaching the upstream API | high | mitigate | `updateBoardBodySchema` gates the body server-side before any upstream call, returning 400 without one on failure (ASVS V5). React Hook Form's client validation is display convenience only — the Route Handler is callable directly with any body. |
| T-02-58 | Repudiation | Optimistic rename rolled back silently | high | mitigate | An unannounced rollback would leave the user believing a rename persisted when it did not. `onError` restores the exact snapshot AND raises a danger toast with authored copy; Task 2 asserts both and the Task 4 checkpoint exercises it with a blocked request.
