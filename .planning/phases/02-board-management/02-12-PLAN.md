## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `renameBoardAction` | A Server Action is callable over the wire with an arbitrary payload; the board id, the name and the version all arrive untrusted, and the version is a value a caller could set to anything |
| Next.js server -> external Kanban backend | The server-derived `userId`, the caller's board id and the optimistic-locking version all cross here |

## Currency note (why this plan was regenerated)

The 2026-08-20 version of this plan built BOARD-04 on a `app/api/boards/[boardId]/route.ts` Route
Handler and a `useUpdateBoard` hook implementing TanStack Query's `onMutate`/`onError`/`onSettled`
lifecycle against a `["boards"]` query cache. Phase 02.1 banned Route Handlers and deleted that cache
entirely — the sidebar reads RSC-supplied props now. docs/adr/tech/0019's Consequences call out the
resulting anti-pattern by name: wrapping a Server Action in a mutation and expecting a cache write to
update a component that never ran a query, when the optimistic apply and rollback belong in local
state instead. D-15's user-visible contract — the sidebar name changes on submit and reverts with an
error toast on failure — is delivered exactly; only the mechanism moved, to the shape
`use-theme-preference.ts` already ships and the ADR names as the reference. The old plan's claim that
the dashboard header updates with the optimistic rename was an artifact of the shared query cache and
is not carried forward silently: it is scoped out, commented in the code, and raised for decision at
the Task 4 checkpoint.
