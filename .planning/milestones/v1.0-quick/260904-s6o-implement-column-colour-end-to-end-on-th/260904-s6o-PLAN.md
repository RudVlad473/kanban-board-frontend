<objective>
Ship column colour end to end on the frontend against the regenerated OpenAPI contract: a curated,
ordered palette whose entries are provably distinct in OKLab, a first-unused picker that reads the
colours actually RENDERED on the board, and the write/read wiring that carries a colour from the
create modal to the backend and back onto the header dot.

Purpose: the backend now serves `ColumnResponseDTO.color` and accepts `SaveColumnRequestDTO.color`
on create, and every column that exists today returns null. Nothing on the frontend reads or writes
that field, so the feature is invisible. The defect this design exists to prevent is a new column
being given a colour that collides with a legacy neighbour's DISPLAYED hue — which is why the
picker's input is `column.color ?? idDerivedFallback(column.id)`, never the stored colour alone.

Output: the regenerated contract committed; an OKLab distance module; a palette constant carrying
its own distinctness invariant as a test; a picker with three tested branches; the zod boundary and
`#RRGGBB` validator the contract does not carry; the create action and hook wired; both dot render
sites reading a stored colour; an e2e round trip; and a human sign-off on how the palette looks.
</objective>

   and nothing recolours one.

   `color` field, so colour is set once at creation and a bad pick is unrevertible per column.
   Background contrast is deliberately NOT a palette constraint: two of the three shipped accents
   already miss WCAG 1.4.11's 3:1 non-text bar against the light canvas (`#49C4E5` 1.90,

   `aria-hidden` decoration beside a text label that carries the meaning.

6. **Reconciliation of the 0.15 floor, resolved at planning time — implement this reading.**
   The brief states both "every pair in the palette is at least ΔE_ok 0.15 apart" AND "the five NEW
   entries must clear 0.15 against every other entry including these three". Those cannot both hold
   literally: the mock's own pair `#49C4E5`/`#67E2AE` measures **0.134**, below the floor, and the
   mock's accents are not ours to change. The invariant to implement is therefore: **every pair is
   >= 0.15 EXCEPT the single grandfathered shipped pair (palette indices 0 and 2), which is pinned
   at 0.134 exactly.** Pin it as an equality, not as a skipped case, so a change to either shipped
   accent fails loudly rather than widening the exemption.

7. **Every new test is falsified in both directions, and the SUMMARY says which.** Run it against
   the absent/unfixed implementation, observe FAIL; run it against the implementation, observe PASS.
   For the palette invariant specifically, falsify by temporarily inserting a deliberately-too-close
   entry, watching it go red, and reverting.
