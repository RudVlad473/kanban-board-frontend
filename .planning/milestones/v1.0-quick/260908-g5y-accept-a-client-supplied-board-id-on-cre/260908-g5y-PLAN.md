<objective>
Let the client mint the board's id and send it on create, so the board's id is known before the
server answers.

Purpose: `router.push()` cannot fire until `createBoardAction` returns, because the destination path
needs the server's id and `app/(dashboard)/boards/[boardId]/page.tsx`'s membership guard (T-02-54)
redirects away from an id it cannot find. Measured round trip: 659-1439ms
(`.planning/debug/board-create-optimistic.md`). Moving id generation to the client removes that
dependency at its root. This plan lands the id half only; the navigation that becomes possible
because of it is quick task 260908-g5z.

Output: a regenerated API contract, a board-id minter, the id threaded through the action and the
create hook, the now-pointless id swap deleted, the comments that describe the old mechanism
corrected, and three test layers proving it.

**Ordering.** This is the second of five sibling quick tasks, and they are SEQUENTIAL, not parallel:
`260908-g4p` (Q1) → **`260908-g5y` (this plan)** → `260908-g61` (Q4) → `260908-g5z` (Q3) →
`260908-g63` (Q5). Q1, this plan and Q3 all rewrite
`src/features/boards/hooks/use-create-board.ts`, and Q3 and Q4 both rewrite `board-screen.tsx`, so
any two of them running at once conflict in the same file.

Two consequences that bind this plan specifically. **Upstream:** Q1 has already retired
`BOARDS_QUERY_KEY` by the time this runs — see the `key_links` entry for what replaces it, and read
the hook as it actually stands rather than as this plan quotes it. **Downstream:** Q3 HARD-depends
on this landing and merging first (it says so in its own frontmatter), and it branches on the
`withBoardReplace` decision Task 3 makes. That decision is this plan's to make and the summary must
state which way it went.
</objective>

**The minter.** New module `src/features/boards/board-id.ts` exporting `mintBoardId()` and the
pattern it satisfies, so the mint and the check are one declaration and cannot drift. Draw 13
characters from `[0-9a-z]` using `crypto.getRandomValues`, with rejection sampling — discard bytes
at or above 252, the largest multiple of 36 below 256 — because a bare `% 36` over raw bytes biases
the first four symbols. 13 is the backend's ceiling (`Long.toString(Long.MAX_VALUE, 36).length()`),
which makes the space 36^13. Give the file a `// Covered by:` header pointing at its unit test
(`pnpm coverage:check` enforces this) and keep it free of `"use client"` — the server action reaches
its exported pattern through `schemas.ts`.

optimistic row cannot predict — the exact failure this task exists to remove. A Server Action is
callable over the wire with an arbitrary payload, so this is the runtime defence T-02-45 requires
(docs/adr/tech/0024), and it is what refuses a hostile id before it reaches the upstream call.
