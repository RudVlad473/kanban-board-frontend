in `vitest.config.ts`.

per-action storybook stub set.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-13 | Spoofing | `src/features/auth/actions/sign-in.ts` | high | mitigate | The split must preserve the single fixed `INVALID_CREDENTIALS_MESSAGE` for every failure branch — a wrong email and a wrong password must stay byte-identical responses (T-01-08, account enumeration). Task 1 forbids changing any message string and the moved tests assert the branch equality. |
| T-02-14 | Elevation of Privilege | `src/features/theme/actions/update-theme.ts` | high | mitigate | The session check must stay first, before validation, and `userId` must keep coming from `verifySession()` rather than any caller-suppliable argument (T-01-05/T-01-06). The moved test file asserts both, unchanged. |
| T-02-15 | Tampering | `"use server"` directive placement | high | mitigate | Each new action file must open with `"use server"` on line 1; a split that dropped or misplaced it would turn a server-only mutation into a client-bundled function exposing `externalApi`'s import chain. Task 1/2 acceptance criteria assert line 1 of every new file. |
| T-02-16 | Information Disclosure | `src/test-utils/*-storybook-stub.ts` reaching application code | low | mitigate | Stubs live under `src/test-utils/` and are reachable only through the `storybook` Vitest project's alias array — never imported by application source (CONVENTIONS.md's `test-utils` rule). Task 3 makes `pnpm test:a11y` a first-class acceptance criterion rather than relying on `tsc`, which cannot see Vite aliases. |
