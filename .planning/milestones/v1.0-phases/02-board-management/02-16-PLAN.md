<objective>
Three small, already-approved UX/quality follow-ups surfaced during this session's checkpoints on
BOARD-02/03/04, folded into one supplemental plan rather than three: extract rename's ad-hoc
upstream-error mapping into a shared module and give board creation the same duplicate-name
recognition it lacks (D-01); close the rename modal the instant it is submitted instead of waiting
on the network round trip, since the optimistic override already made the change visible
underneath it (D-02); and give board-switching an instant skeleton via Next's own loading.tsx
convention instead of a silent wait on the blocking membership check (D-03).

Purpose: closes a real gap (a duplicate board name gives the user no more information on create
than a generic "try again", though the identical refusal on rename already explains itself) and two
perceived-latency papercuts explicitly separated from the OUT-OF-SCOPE items logged in
deferred-items.md (delete's responsiveness, board-creation-as-optimistic-append, soft-delete) —
this plan is deliberately narrower than any of those.
Output: one shared error-mapping module with its own unit test; create-board.ts and its hook
recognising a duplicate name distinctly; board-list.tsx closing the rename modal on submit rather
than on settle; and two Next.js loading.tsx files giving board navigation an instant fallback.
</objective>
