visual regression — as its own dedicated, smoke-verified step, before the first primitive exists.

reactively while building Button. D-21 requires axe-core wired from the very first primitive so

as stories ship rather than batched at the end. All three only hold if the harness exists first.

Playwright visual project, a throwaway smoke component proving all three run, and CI jobs that
execute them.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → developer machine and CI runner | Nine new test-tooling packages plus a downloaded browser binary execute locally and in CI |
| browser binary download → CI runner | Playwright fetches chromium at install time on every CI run |
| built Storybook → visual test runner | The static Storybook is served over HTTP to the screenshot runner |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-SC | Tampering | Vitest, Storybook, Playwright and testing-library installs | high | mitigate | All cleared by the RESEARCH.md legitimacy audit and the blocking checkpoint in plan 01-01; every version pinned in `pnpm-lock.yaml`; CI installs with `--frozen-lockfile` |
| T-01-20 | Tampering | Playwright browser binary fetched at CI install time | medium | mitigate | Fetched via `playwright install` from Microsoft's own distribution, version-pinned by the `@playwright/test` dependency; no third-party mirror configured |
| T-01-21 | Spoofing | Visual baselines captured on an untrusted or mismatched host and committed as truth | medium | mitigate | `ignoreSnapshots` off-CI plus a `workflow_dispatch`-only baseline workflow makes CI the only writer of baselines, turning ADR tech/0008's stated-but-unenforced constraint into a mechanical one |
| T-01-22 | Information Disclosure | Storybook static build served in CI | low | accept | The built Storybook contains only design-system components with no credentials or user data, is served on the ephemeral runner only, and is never deployed |
</threat_model>
