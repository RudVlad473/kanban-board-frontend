<objective>
Turn on the three-ring boundaries policy and move the whole pure ring of `src/lib/` into
`src/lib/core/`, subdivided by concern, updating every importer. This is round-4 gap closure
GC-25 (three-ring split) and GC-28 (mechanical enforcement) for the pure ring only; the server and
client rings and the feature-local moves are plan 01-37, and the documentation is plan 01-38.

Purpose: `src/lib/` is a flat catch-all that mixes pure helpers with server-only secret-holding
infrastructure and browser-coupled infra, with nothing in the folder structure signalling which is
which — the exact ambiguity that produced the 01-33 Storybook stub. The three-ring split makes the
platform coupling of every module structural and lint-enforced rather than a convention a reader has
to know.

Purpose of doing the eslint change first, in this plan's tracer, AND why it needs transitional
legacy elements: the flat `lib` element pattern is `src/lib/*`, which matches only direct children of
`src/lib/` and does not match a nested file like `src/lib/core/styling/cn.ts` (verified with
micromatch during planning). `boundaries/dependencies` is configured `default: "disallow"`.

There are two failure modes to avoid, and the naive "just swap the flat element for the three ring
patterns" fix (as originally written and flagged HIGH in 01-REVIEWS.md #1) only avoids the first:

1. If we kept the flat `src/lib/*` element and moved `cn.ts` into `src/lib/core/styling/`, the moved
   file would match no element and its importers would be disallowed. So the ring `**` patterns must
   exist before the first move. (This is what the original plan got right.)

2. But if we DELETE the flat `src/lib/*` element and add only the three ring `**` patterns, then the
   files that have NOT moved yet — `routes.ts`, `session.ts`, `dal.ts`, `server-client.ts`,
   `query-client.tsx`, `display-name.ts`, `validation/auth-schemas.ts`, and the rest, which don't
   move until later tasks in this plan and in 01-37 — match none of the three ring patterns
   (`src/lib/*`-style flat and `src/lib/api/*`/`src/lib/validation/*` folder files are all disjoint
   from `src/lib/core/**` etc.). With the disallow default, every existing `feature -> @/lib/session`,
   `ui -> @/lib/...` edge resolves its `to` element to nothing and is rejected, and `pnpm lint` fails
   the instant the flat element is removed — before a single file has moved. This is the exact bug
   01-REVIEWS.md #1 (orchestrator-verified) identified in the original Task 1.

The fix (01-REVIEWS.md Suggestion #1): keep the three ring `**` patterns AND three transitional
`lib-legacy` element patterns that continue to capture the still-flat files by their current
locations — `lib-legacy` (`src/lib/*`), `lib-legacy-api` (`src/lib/api/*`), `lib-legacy-validation`
(`src/lib/validation/*`) — with a permissive transitional policy so any importer (feature/ui/layout
and the three rings) may reach a not-yet-moved legacy file, and a legacy file may reach anything.
Ring patterns are listed first so a moved file resolves to its ring, never to legacy (the patterns
are disjoint anyway — verified with micromatch — but ring-first ordering makes the intent explicit).
As each file moves out of a flat location into a ring, it stops matching legacy and starts matching
its ring; lint stays green at every step. Plan 01-37 Task 3, once the last flat file has moved, deletes
the three `lib-legacy` element patterns and their transitional policies, leaving only the strict
three-ring policy.

Output: the eslint config carries three `lib-*` ring element types with GC-25's ring directionality
plus three transitional `lib-legacy*` elements (removed in 01-37 Task 3), and `src/lib/core/` holds
the pure ring in four concern subfolders with every importer repointed.
</objective>
