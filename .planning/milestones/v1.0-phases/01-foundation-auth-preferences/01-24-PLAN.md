<objective>
Close GC-15: fix TextField's `isLoading` state so it is actually visible, not merely inert.

Purpose: 01-16 (already merged) gave TextField's `isLoading` a `readOnly` (not `disabled`) mechanism
plus an `isBusy` cva axis contributing only `cursor-progress`. A source-level read confirms the exact
defect: `cursor-progress` alone produces no visible difference until a pointer sits over the field and
a sighted user studies the cursor glyph — no opacity, background, or border change accompanies it,
unlike every other state this primitive renders (idle, error, disabled). This task must confirm the
finding live before changing anything, then land a real visual treatment that reads as its own
distinct "busy" state — not identical to idle, and not identical to disabled either, since a loading
field is neither.
</objective>

<decisions>
**The readOnly-not-disabled mechanism is unchanged — this is a visual fix, not a redesign.** D-16's
decision (a loading field stays focusable rather than being blurred mid-typing) is correct and stays
exactly as 01-16 wrote it. Only the `isBusy` cva branch's class list changes.

**The fix must be visually distinct from both idle and disabled, not merely "not idle."** A loading
field is neither fully available (idle) nor unavailable (disabled) — it reads as its own state:
reduced opacity below idle's 1.0 but above disabled's 0.5, so a user scanning the form can tell "busy"
from "broken" at a glance, and a background tint distinguishes it from the crisp `bg-bg-surface` of an
active field.
</decisions>
