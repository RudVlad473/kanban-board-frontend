    <action>
Create `e2e/seed.sh` — a standalone bash script, placed in `e2e/` next to the specs that use it
rather than in `scripts/`, because its lifecycle is per-test seeding rather than repo tooling
(02.1-RESEARCH.md §4 resolves this discretion point). Open with `#!/usr/bin/env bash` and
`set -euo pipefail`, and a header comment of at most three prose lines naming D-07 and pointing at
`docs/adr/tech/0022` for the reasoning.

Structure:
- Read the backend base URL from `EXTERNAL_API_BASE_URL` in the environment; exit non-zero with a
  clear message if it is unset (the Node wrapper passes `E2E_CONFIG.EXTERNAL_API_BASE_URL` through).
- Constants ported verbatim from `e2e/fixtures.ts`: the fixture password (satisfies the backend's
  8-64 chars / upper / lower / digit / special rule) and the fixture display name (satisfies the
  3-32 letters-and-spaces rule — no digits). Keep a one-line comment on each stating the rule it
  satisfies.
- Subcommand `account`: create a cookie jar with `jar=$(mktemp)` plus `trap 'rm -f "$jar"' EXIT`,
  generate a randomised email, `curl -sS -f -c "$jar" -X POST "$base/signup"` with a JSON body,
  capture the response body, extract the created `id` (use `jq` if present, otherwise a `node -e`
  one-liner — do not depend on `jq` unconditionally, its availability was not confirmed), read the
  `JSESSIONID` value out of the jar file rather than reparsing `Set-Cookie` headers (the jar stores
  each cookie as its own entry, which is exactly the collapsing problem `extractJsessionId` exists
  to work around), and print one JSON line with all five fields.
- Subcommand `board`: take `--jsession`, `--user` and `--name`, then
  `curl -sS -f -X POST "$base/boards?userId=$user" -H "Cookie: JSESSIONID=$jsession" -H "Content-Type: application/json" -d "{\"name\":\"$name\"}"`
  and print the response body. Reusing the passed-in credential rather than signing in again is the
  session-budget constraint this port must preserve.
- Any other subcommand: print a usage line and exit 2.
- Make the file executable (`git update-index --chmod=+x e2e/seed.sh` after adding it, so the mode
  bit is committed).

Create `e2e/seed.ts` — a thin typed wrapper, the only thing specs import:
- `export type SeededAccount = { id: string; email: string; password: string; displayName: string; jsessionId: string };`
- `export const seedAccount = (): SeededAccount => { ... }` and
  `export const seedBoard = ({ account, name }: { account: SeededAccount; name: string }): { id: string; name: string; version: number } => { ... }`,
  each running `spawnSync("bash", ["e2e/seed.sh", ...args], { env: { ...process.env, EXTERNAL_API_BASE_URL: E2E_CONFIG.EXTERNAL_API_BASE_URL }, encoding: "utf8" })`,
  throwing an `Error` carrying `result.stderr` when `result.status !== 0`, and `JSON.parse`-ing
  `result.stdout`.
- Invoke via `bash` explicitly rather than relying on the shebang, so the script also runs on the
  Windows dev machine this project is developed on (Git Bash supplies `bash`); note that in one line.

Rewrite `e2e/boards-list.e2e.spec.ts` to use `seedAccount()`/`seedBoard(...)` instead of
`createFixtureAccount`/`createFixtureBoard`, and add `// Arrange` / `// Act` / `// Assert` comments
to its body (D-06). Leave its assertions alone in this task — the D-05 scope trim happens in Task 3.

Add `"e2e:seed": "bash e2e/seed.sh"` to `package.json`'s scripts so the CLI is invocable by hand
for debugging.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| seeding script → shared nonprod backend | `seed.sh` creates real, permanent accounts and boards on a backend shared with CI and other developers |
| test arguments → shell command | Board names and emails flow from TypeScript into a bash script's `curl` invocation |
| CI runner → seeding script | The `e2e` job runs `seed.sh` with the workflow's own environment |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.1-33 | Tampering | shell argument injection into `seed.sh` | high | mitigate | `e2e/seed.ts` invokes `spawnSync("bash", [script, ...args])` with an argument array — never a concatenated shell string and never `shell: true` — so a board name containing shell metacharacters is passed as one literal argument. Inside the script every expansion is double-quoted and `set -euo pipefail` is on. Board names in specs are generated from `randomUUID()`, not from user input. |
| T-02.1-34 | Information Disclosure | the fixture password in a committed script | medium | accept | The password is an explicitly non-production fixture value already committed in `e2e/fixtures.ts` today; moving it into `seed.sh` changes nothing about its exposure. Accepted, unchanged risk. |
| T-02.1-35 | Information Disclosure | JSESSIONID written to a temp file | medium | mitigate | The cookie jar is created with `mktemp` (mode 600, per-process path) and removed by a `trap ... EXIT` so it does not survive the script, including on failure. |
| T-02.1-36 | Denial of Service | two-concurrent-sessions-per-account cap | medium | mitigate | `seed.sh board` reuses the passed-in `JSESSIONID` rather than signing in again — the exact constraint `e2e/fixtures.ts` lines 51-66 documents. A spec that also drives the real sign-in form still has one session left. |
| T-02.1-37 | Repudiation | orphaned accounts on shared nonprod | medium | mitigate | Unchanged: `e2e/global-setup.ts`'s `/admin/reset` precondition and CI's post-suite reset step both stay in place, and this plan explicitly does not fold seeding into global setup. |
| T-02.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | No packages installed by this plan; `curl` 8.21.0 is already present on the dev machine and on the CI runner, and `jq` is used only behind an availability check with a `node -e` fallback. |
</threat_model>
