# Phase 02.1 Plan 02: Testing/Code-Quality Enforcement Mechanisms Summary

**Built and proved two automated CI gates — a path-scopable comment-length checker (D-22) and an
ESLint ban on Vitest module mocks outside Storybook (D-04/D-19) — both starting at non-blocking
severity ahead of the retrofit sweeps that will flip them to blocking in plan 02.1-15.**

## Accomplishments

- `scripts/check-comment-length.mjs` exports a pure `findLongCommentRuns({ source, max })`
  classifier (unit-testable without touching disk) plus a CLI entry point mirroring
  `scripts/check-routes.mjs`'s shebang/header/`globSync`/violations-array/exit-code shape.
  Path-scopable: no arguments scans the whole repo via a default glob list; a directory argument
  expands to `<dir>/**/*.{ts,tsx,mjs}`; any other argument passes through as a raw glob.
- `scripts/check-comment-length.unit.test.mjs` (8 tests, all passing) covers every `<behavior>`
  bullet from the plan — over-limit detection, exactly-at-limit compliance, delimiter/spacer
  non-counting, blank-line run termination, the `comment-length-exempt:` marker (both the
  immediately-adjacent-works and too-far-away-doesn't-apply cases), a no-comments file, and a
  real-file read of `text-field.tsx` asserting its known 26-prose-line offender is found.
- `pnpm comments:check` (package.json) and a non-blocking `Comment length check` CI step
  (`continue-on-error: true`, immediately after `Format check`) are both wired and run the same
  script `node scripts/check-comment-length.mjs` uses directly.
- `eslint.config.mjs` gained a `no-restricted-properties` block (warn severity) flagging
  `vi.mock`/`vi.spyOn` on `*.{ts,tsx}` files, excluding `*.stories.{ts,tsx}` (D-19's Storybook

  framework/environment-shim exception, matching the wording the plan specified.
- Proved against real offenders: `pnpm lint` reports the ban firing on all 13 currently-violating
  test files (25 individual `vi.mock`/`vi.spyOn` call sites) at warn severity, `pnpm lint` still
  exits 0, and zero `Unused eslint-disable directive` warnings appear anywhere in the run.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `no-restricted-syntax` rule-config clobbering, discovered while implementing
Task 2 exactly as the plan's action text specified**
- **Found during:** Task 2, first `pnpm lint` run after adding the plan-specified second
  `no-restricted-syntax` config object (scoped to `**/*.{ts,tsx}`, ignoring stories files) with
  the two `vi.mock`/`vi.spyOn` selectors at `"warn"`.
- **Issue:** ESLint flat config replaces — does not merge — a rule's configuration per matching
  file when two config objects both set the same rule key. Section 8d's pre-existing
  `no-restricted-syntax` block (no `files` filter, so it matches every file including `.tsx`) sits
  *before* the plan's new block in array order; the new block's narrower-but-still-universal
  `files: ["**/*.{ts,tsx}"]` scope meant it fully overrode section 8d's rule config for every
  `.ts`/`.tsx` file — silently dropping the `TSImportType`, positional-argument, and raw-`<a>`
  selectors everywhere. Confirmed empirically: the first `pnpm lint` run surfaced 42 problems
  including "Unused eslint-disable directive" warnings on 10+ unrelated files (`app/page.tsx`,
  `sign-in.ts`, `sign-out.ts`, `sign-up.ts`, `sign-in-form.tsx`, `sign-up-form.tsx`, several
  `*.test.ts(x)` files) whose pre-existing `eslint-disable-next-line no-restricted-syntax`
  comments (guarding the raw-`<a>` and positional-arg bans) had gone silently unused because those
  selectors no longer applied to those files at all.
- **Fix:** Switched the new block to ESLint's core `no-restricted-properties` rule instead of a
  second `no-restricted-syntax` instance — a distinct rule ID has its own independent config slot,
  so it coexists with section 8d's `no-restricted-syntax` block without any override risk.
  `no-restricted-properties` is purpose-built for exactly this `object.property` access shape
  (`{ object: "vi", property: "mock", message }`), so no expressiveness was lost; the escape-hatch
  directive text changed to name `no-restricted-properties` instead of `no-restricted-syntax`
  (the only literal deviation from the plan's specified message wording).
- **Files modified:** `eslint.config.mjs`
- **Verification:** `pnpm lint` exits 0; `grep -c "Unused eslint-disable directive"` on the lint
  output prints 0; all pre-existing selectors (raw `<a>`, positional-arg, `TSImportType`) confirmed
  still firing correctly (re-verified via the same full `pnpm lint` run).
- **Committed in:** `16f56ba` (the fix is folded into Task 2's single commit — the broken
  intermediate state was never committed)

**2. [Rule 1 - Bug] `EISDIR` crash on the repo-wide (no-argument) `check-comment-length.mjs` run**
- **Found during:** Post-Task-2 full-plan `<verification>` pass (`node
  scripts/check-comment-length.mjs` with no arguments, required by the plan's own verification
  block).
- **Issue:** Playwright's `toHaveScreenshot()` creates a same-named *directory* per visual spec
  file (`visual/__screenshots__/primitives.visual.spec.ts/`) to hold baseline PNGs. The default
  `"visual/**/*.ts"` glob matched this directory's name as if it were a file, and
  `scanFile`'s `readFileSync` crashed with `EISDIR` the moment it tried to read it. This did not
  surface during Task 1's own acceptance-criteria checks because none of them targeted `visual/`
  or ran the full default-glob (no-argument) scan.
- **Fix:** Added an `isRealFile()` guard (`statSync(...).isFile()`) to the file list before any
  read is attempted, filtering out directories that happen to match a glob's extension pattern.
- **Files modified:** `scripts/check-comment-length.mjs`
- **Verification:** `node scripts/check-comment-length.mjs` (no args) now exits 1 cleanly, finding
  88 distinct real offender files across the repo, instead of crashing.
- **Committed in:** `7556137`

### Accepted, Not Auto-fixed

**3. `pnpm format:check` reports one pre-existing formatting issue in
`.claude/settings.local.json`, an untracked harness-generated worktree-scaffolding file.**
- **Why:** This file is not part of git history (`git status --short` shows it as `??`), is not
  in this plan's `files_modified` list, was not created or touched by any task in this plan, and
  is regenerated by the Claude Code worktree tooling itself for every isolated session — not
  application code. `.gitignore` only excludes `.claude/worktrees/`, not `.claude/` itself, so
  Prettier's `--check .` glob still reaches it.
- **Not fixed because:** It is out of scope per the deviation rules' scope boundary (only
  auto-fix issues directly caused by the current task's changes); formatting a file that is never
  committed would have no lasting effect and risks masking a real signal if the harness ever
  changes that file's expected shape.
- **Verified in scope instead:** `pnpm exec prettier --check` run explicitly against every file
  this plan actually created or modified (`eslint.config.mjs`, `scripts/check-comment-length.mjs`,
  `scripts/check-comment-length.unit.test.mjs`, `package.json`, `.github/workflows/ci.yml`)
  reports "All matched files use Prettier code style!" — this plan's own `pnpm format:check`
  requirement is satisfied for every file it is responsible for.
