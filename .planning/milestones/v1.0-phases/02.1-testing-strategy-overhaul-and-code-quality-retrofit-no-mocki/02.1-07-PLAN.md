<objective>
Route the shallow assertions in five UI primitives' tests through their own composed Storybook
stories.

Purpose: D-08 requires every component's test file to import its stories via `composeStories` and
cover shallow concerns — copy text, prop-driven variants, validation and error-state rendering — so
that the coverage e2e gives up under D-05 lands somewhere real, and so a story and its test can
never drift into describing different components. 02.1-RESEARCH.md verified the portable-stories
wiring is already present in `vitest.setup.ts` and used nowhere; plan 02.1-01 proved it works on
`sidebar.test.tsx`. This plan scales that proven pattern to the first five primitives.

Output: five test files driving their shallow coverage through composed stories, with any missing
stories added so every asserted state has a named story.
</objective>

For `button.test.tsx` and `icon-button.test.tsx`, in each file:

1. Add `import { composeStories } from "@storybook/react";` and `import * as stories from "./<name>.stories";`
   — from `@storybook/react`, never `@storybook/nextjs-vite`, whose main entry eagerly imports
   Next.js internals the "browser" Vitest project deliberately does not load (`vitest.setup.ts` lines
   27-42 documents this in full; keep the reference to it to one line here).
2. Classify every existing assertion in the file into one of two buckets, and act accordingly:
   - **Shallow** — visible copy, `aria-*` attribute values driven by props, disabled/loading/error
     state rendering, which variant/size class is applied, accessible name. Rewrite it to run against
     a composed story: `const { Primary, Destructive, Loading, Disabled } = composeStories(stories);`
     then `await Primary.run();` and assert through `screen` queries from `@testing-library/react`.
   - **Deep** — assertions calling `getComputedStyle()` against Tailwind custom-property-driven
     tokens, axe checks, real focus/keyboard behaviour, pointer-event behaviour. Keep the existing
     direct render (`renderWithProviders`), and add a one-line comment on that block stating it needs
     real rendering rather than a composed story. Do not delete deep coverage to make the file
     uniform.
3. If a shallow assertion has no story expressing its state, ADD the story to the sibling
   `*.stories.tsx` rather than staging the props inline in the test. That is the whole point of
   D-08 — the story becomes the shared description. Give each new story a name matching the state it
   shows (`Loading`, `Disabled`, `WithIconOnly`, ...) and give it the mobile/desktop viewport
   treatment the other stories in the file already use.
4. Keep the `describeForEachDevice` wrapper around the whole suite (CONVENTIONS.md's dual-viewport
   rule is unchanged by this phase) and keep `// Arrange` / `// Act` / `// Assert` comments in every
   body, adding them where missing.
5. Compress any comment block in the touched files whose prose exceeds three lines (these files are
   in plan 02.1-11's sweep scope, but a file rewritten here must land compliant so the sweep is not
   re-doing this work).
