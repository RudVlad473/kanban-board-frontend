<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Next.js server → external API | The path string decides which backend resource is called and, via `server-client.ts`'s `UNAUTHENTICATED_SCHEMA_PATHS`, whether a 401 clears this app's session |
| test config → spawned web server | `playwright.config.ts` forwards `SESSION_SECRET` into the `next start` process it spawns |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.1-13 | Tampering | `UNAUTHENTICATED_SCHEMA_PATHS` | high | mitigate | This set decides whether an upstream 401 forcibly destroys the user's session. A path literal drifting by one character silently disables that behaviour for sign-in/sign-up. Replacing the literals with `EXTERNAL_PATH` members plus the compile-time contract-key assertion makes drift a type error rather than a silent behaviour change. |
| T-02.1-14 | Spoofing | a wrong external path reaching production | medium | mitigate | The `external-paths.unit.test.ts` compile-time assertion against `keyof paths` fails the build if a declared member is not a real contract path; `routes:check` fails the build if a literal reappears outside the declaration file. |
| T-02.1-15 | Information Disclosure | `E2E_CONFIG.SESSION_SECRET` | low | accept | The fallback value is an explicitly non-production string and is only reached when no real `SESSION_SECRET` is set; CI always generates a real workflow-scoped secret. Grouping the exports does not change what is read or where it flows. Accepted, unchanged from today's behaviour. |
| T-02.1-SC | Tampering | npm/pip/cargo installs | high | mitigate | No packages installed by this plan. |
</threat_model>
