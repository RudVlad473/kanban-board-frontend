<sweep_procedure>
Every task in this plan follows the same procedure. Read it once, apply it three times.

1. Run `node scripts/check-comment-length.mjs <the task's paths>`. Its output is the worklist:
   each line names a file, the run's start line, and its prose length. Do not guess at offenders.
2. For each reported run, open the file and read the comment in full. Decide which single sentence
   carries the WHY a reader needs at that call site, and where the rest already lives. In this
   repository the rest almost always already exists in `docs/adr/tech/NNNN`, a phase `CONTEXT.md`,
   or a plan `SUMMARY.md` — the comment is restating it, which is precisely the defect PC-05 names.
3. Rewrite the comment as at most three prose lines, ending in a short pointer of the form
   `(see docs/adr/tech/0021)` or `(see 01-29-SUMMARY.md)`. If you cannot find where the rationale
   lives, it has no durable home — add it to the relevant ADR in `docs/adr/tech/` first, then point
   at it. Never delete a rationale that exists nowhere else.
4. Use the `comment-length-exempt: <reason>` marker only where compression would genuinely destroy
   information a reader needs inline and no durable home fits. Expect this to be rare; each use must
   state its reason.
5. Change nothing but comment text. No identifier renames, no reordering, no logic edits.
6. Re-run the checker for the task's paths until it exits 0, then run the task's test command.
</sweep_procedure>
