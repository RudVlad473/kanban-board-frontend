<objective>
Deliver COLUMN-04: a `Delete Column` entry on the column kebab, a confirmation that mirrors the
shipped board-delete confirm exactly, and a delete that waits for the server before removing anything
from the screen.

Purpose: this is the only operation in this phase that cannot be undone. The cascade to tasks and
subtasks happens server-side and the frontend has no way to detect a non-empty column beforehand or
to restore one afterwards, so every guard here is load-bearing: the confirmation names the column,
the non-destructive button holds focus, and nothing disappears from the board on optimism.

Output: COLUMN-04 satisfied, with the second and final entry on the column kebab.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Server Action | `deleteColumnAction` is callable over the wire with an arbitrary payload regardless of its compile-time signature (ADR tech/0024). |
| Server Action → deployed backend | One `DELETE` triggers an irreversible server-side cascade to tasks and subtasks (ADR domain/0002). |
| user intent → destruction | A single confirmation dialog is the only thing between a mis-click and permanent data loss. |
