**Auto-scroll (D-04).** Attach a ref to the `AddColumnPlaceholder` element — it is always the last
child of the row and always sits immediately after the newest column, so bringing it into view brings
the new column into view too, with no id bookkeeping. On a successful create, set a pending-scroll
flag; in an effect that depends on the rendered column count, scroll when the flag is set and then
clear it. The effect must run *after* the refreshed props land, because the action's `refresh()` is
what grows the row — scrolling at the moment of success would scroll the row as it was before the new
column existed.

Call the scroll with the inline alignment that brings the end of the row into view and the nearest
block alignment, and pass **no** behavior argument. Put the smooth-scroll utility and its
reduced-motion opt-out on the scroll row itself. This is the whole reduced-motion story: a JavaScript
smooth-scroll cannot be varied by a CSS reduced-motion variant, so the one CSS declaration on the row
governs both the motion and its opt-out.

**Count nudge (D-03/D-05).** Give `useCreateColumn` a `columnCount` argument (the board's current
column count, passed from the container) and a `useToast()`. After a successful create, call
`shouldNudgeOnColumnCount({ nextCount: columnCount + 1 })` from `model.ts` and, when it returns true,
raise one toast.

Author the copy here, in the hook, alongside the failure table — it is a title/description pair like
every other toast in this codebase. Use:

- title: `That's 9 columns on this board.`
- description: `Columns scroll horizontally from here.`

It states a fact about the board and stops. It must not scold, must not call the board messy or
excessive, must not suggest the user has done something wrong, and must not offer or imply an undo —
the create succeeded and D-02 is that column count is uncapped.

Raise it in the shipped `Toast`'s neutral treatment, not the danger one: the danger accent is
reserved for failures and nothing failed. Do not give the toast an id or a zero timeout — it is a
transient informational message, so the plain title/description call the rename hook already uses is
the right shape.

The nudge fires strictly after the success branch has been taken, so it can never delay, gate, or
alter the create. Add `EightColumns` to `board-view.stories.tsx` (a board built with eight columns, so
the next create is the 9th) and add the behaviour cases above to `board-view.test.tsx`.
