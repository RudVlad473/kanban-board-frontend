<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| wire → Server Action argument | A Server Action is callable over the wire with an arbitrary payload regardless of its compile-time types (ADR tech/0024). The schemas defined here are the only thing standing between that payload and the upstream call. |
| RSC props → client derivation | `applyColumnOrderOverride` consumes server-supplied column arrays; it must not trust that an override's ids still exist. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | `createColumnInputSchema` / `renameColumnInputSchema` / `deleteColumnInputSchema` | high | mitigate | Each action's own arguments are `safeParse`d against these schemas, ids as `z.string().min(1)` and names through the shipped 3-32 `columnNameSchema`. Task 1's boundary cases prove the refusals are real, not declared. |
| T-03-06 | Tampering | `reorderColumnInputSchema.targetPosition` | medium | mitigate | `z.number().int().min(0)` mirrors the contract's own `minimum: 0`, so a negative, fractional, or non-numeric `targetPosition` is refused at this app's boundary. Asserted directly in Task 1's Test 6. |
| T-03-04 | Tampering | optimistic-lock bypass by omitting `version` | high | mitigate | `version` is required in both `renameColumnInputSchema` and `reorderColumnInputSchema`, matching the two request DTOs' own `required` arrays. Task 1's Test 5 proves an input without it is refused rather than silently sent. |
| T-03-19 | Denial of Service | unbounded upstream loop driven by a forged array | low | accept | All four column mutations are single-item; no array reaches the upstream call, so the `.max(50)` cap `createBoardColumnsInputSchema` needs has no analogue here. Recorded so a future batch endpoint does not inherit the omission by default. |
| T-03-20 | Tampering | `applyColumnOrderOverride` fed an override naming a deleted column | low | mitigate | The derivation returns the server's own array whenever the server order or length no longer matches `previousOrder`, and maps with an empty-array fallback for an unknown id, so a stale override can never synthesise or drop a column. Tests 4 and 5 assert both paths. |
| T-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs nothing; `@dnd-kit/*` was installed and audited in plan 03-03. `03-RESEARCH.md` § Package Legitimacy Audit records every entry as **OK/Approved** with `postinstall: null` — no `[ASSUMED]`/`[SUS]`/`[SLOP]` verdict exists in this phase. |
