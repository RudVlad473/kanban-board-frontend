<objective>
Prove all four column endpoints against the real deployed backend, and close the one gap the type
system cannot: the column endpoints whose generated types omit the board-id path parameter.

Purpose: three of this phase's four endpoints have a path type that declares only the column id.
Omitting the board id type-checks cleanly, and the fetch layer skips an unsupplied path parameter
rather than throwing — so the request goes out with the placeholder still in the URL and nothing in
the build, the unit suite, or the browser suite notices. The source assertions in each action's plan
catch a regression in the source text; this suite is what proves the underlying behaviour those
assertions exist to protect against is real.

It is also where the phase's remaining backend assumptions stop being assumptions: the reorder
semantics, the optimistic-lock refusal, the cascade, and the duplicate-name policy each get one
assertion against the running system.

Output: four integration suites in the real-backend Vitest project.
</objective>
